# 独立短剧插件能力审计

审计基线为原项目的标准短剧制作链、内置短剧提示词和相关资产/任务流程。原项目当前包含 284 个 API route，其中大量属于账号、团队、管理后台、支付、积分、云存储和在线资产库；这些不是本地短剧制作能力，不移植。

## 已保留并本地化

## 从原系统能力转换而来

- 数据库项目、剧集、分镜和资产表转换为项目目录、JSON 版本和 SHA-256 资产账本。
- 在线任务服务转换为本地任务账本；Provider 任务 ID 只作为外部回执，不是资产。
- 提示词数据库与 seed 转换为各原子 Skill 自带的中英文模板；固定词表集中在 `controlled-vocabulary.json`，动态项目上下文在调用时生成。
- 原项目 Provider 调用转换为独立 MCP 生成服务；文本不再绕到外部文本模型。
- 原 CLI 的 selected 版本、逐镜验收、字幕、声音平衡、时间线 manifest 和全片验收门禁保留，执行层使用本地 Remotion。

## 明确不保留

- 登录、用户、团队、邀请、权限、管理员后台。
- 支付、积分、套餐、价格发布和用量计费。
- 永久云对象存储、在线素材市场、全局共享资产库和业务数据库同步。只保留为模型传输服务的可选临时参考图发布。
- 在线模板 CRUD、提示词管理后台、通知、SSE 和 Web 页面状态。
- 无限画布、节点编辑器及其节点 ID 合同。

原项目四组制作提示词共有 45 个唯一 stem：38 个按原能力映射，`character_reference_to_sheet` 合并优化为人物完整 `character_asset_sheet`，`panel_h3_video` 重构为独立于画布的 `h3_video`；`character_voice_recommend_cosy` 已去除单一供应商耦合并吸收到通用 `character_voice_recommend`，而 `cat_meme_*`、`director_snapshot_render`、`project_cover_generation` 仍不进入标准短剧插件。插件另补 source analysis、brief、director book、production plan、script review、画风/资产完整设定板和 Seedance 2.0 等标准制作模板，当前合计 52 组中英文模板。

人物视觉不是普通美观评分：`audience_appeal` 先从明确年龄证据区分 `adult-charisma` 与 `child-cuteness`；定妆图逐项审查年龄、身份、妆造服装、`memory_anchors`、观众吸引力及保护标记。任何一项失败都禁止选版。跨镜引用用档案 SHA、`appearance_id` 和 `identity_constraints` 绑定，连续性计划用 `visual_identity` 阻止无剧情证据的换脸、换妆造或换装。

这些能力服务原产品 SaaS，不是“从本地素材到本地成片”的必要步骤；引入它们会重新耦合原系统。

## 当前边界

- StarRouter 当前声明图片、视频、同步语音、语音转写和翻译能力；长文本异步语音返回 TAR，尚未开放为可直接剪辑的音频资产。RunningHub 继续支持用户自定义音频工作流。
- 口型同步可使用 RunningHub 用户工作流或本地 MuseTalk 1.5 连接器。MuseTalk 仅在用户配置 `MUSETALK_ROOT` 后声明 `transform.lip-sync`，插件不携带、安装或下载外部模型；两条路径都必须使用统一媒体操作请求快照、来源版本和专项审核，不能直接覆盖 selected 镜头。
- 音乐目录不提供抓站下载器。在线结果只打开官方搜索入口，登录、试听、下载和当次许可证判断由用户在站点完成；插件只接收本地文件与证据，并在 audio-plan 和时间线两次核对用途。
- 插件不内置大型模型价格表或替用户估价；生成前读取实时 Provider 目录并要求用户确认费用影响。
- Litterbox 免费匿名接口仅用于临时参考图传输，文件公开且受 Catbox 使用条款约束；不保证长期可用，也不替代本地资产。
- Remotion 工程按项目创建，不在插件里复制固定业务工程；这样可保持素材路径、画幅、字幕和交付规格可追溯。

## 外部项目对照审计

2026-09-09 至 2026-09-10 对照 [OSideMedia/higgsfield-ai-prompt-skill](https://github.com/OSideMedia/higgsfield-ai-prompt-skill) `c0b73ab` 与 [eternityspring/shuohao-skills](https://github.com/eternityspring/shuohao-skills) `4322897e`。本插件只吸收可泛化的制作纪律，不复制平台目录、实现代码或原文。

| 结论 | 吸收或跳过原因 |
|---|---|
| 吸收剧本动作可生成性与相邻节拍状态复核 | 补入 `short-drama`，并由 `review-drama-script` 的制作可行性维度复核 |
| 吸收目标—阻力—策略与倾听对象 | 补强 `director_book`；逐镜 `agent_acting_direction` 已有同类结构，不重复建 Skill |
| 吸收症状—机制—单变量修复的审片纪律 | 补入 `review-drama-shots`，连续两次无效即停止盲重试 |
| 跳过固定 2–5 秒切镜、固定语速折算 | 与当前 Provider 4–15 秒素材合同及多语言表演节奏冲突，由制作计划逐镜决定 |
| 跳过 Higgsfield 模型目录、价格、CLI 与记忆库 | Provider 不同；实时模型能力、请求快照和本地账本已有唯一事实来源 |
| 跳过每个 Skill 自带脚本与独立 HTML 报告 | 当前集中审计、集成自检和 Studio 已覆盖，复制会增加维护面 |

### 二轮反向缺口矩阵

| 对照能力 | 当前处理 | 收敛依据 |
|---|---|---|
| 分阶段路由、选版与上游变更失效 | 已有且保留 | 本插件九阶段工作流、不可变版本和哈希失效链比两个对照项目更完整 |
| 结构化文档硬门禁 | 已吸收 | 资产计划、剧本复核、导演本、分镜和视频提示词在写入及选版时统一复验；磁盘篡改不能绕过门禁 |
| 资产证据、版本和派生态 | 已吸收 | 资产计划要求来源定位与原文证据；场景、道具派生版本必须以母版为身份参考且只允许证据支持的变化 |
| Seedance 长镜头时间段连续性 | 已吸收 | 13–15 秒提示词要求从 0 开始、无间隙无重叠并覆盖完整时长，保存时执行确定性校验 |
| 表演目标、阻力、策略、倾听与潜台词 | 已吸收 | 导演本与逐镜表演指令共同承载，不增加重复 Skill |
| 失败分类、单变量修复与停止条件 | 已吸收 | 复用已有任务失败分类，补入症状—机制—单变量修复和两次无效后停止盲重试 |
| 固定 2–5 秒切镜与固定语速阈值 | 明确拒绝 | 当前一个生成镜头可为 4–15 秒，剪辑切点另由时间线控制；多语言对白不能共用固定字数语速 |
| 剧本文本的确定性字段解析 | 暂不引入 | 当前剧本合同允许 JSON、Markdown 和纯文本；若未来统一为结构化剧本，再增加逐行时长和角色引用硬门禁 |
| Higgsfield 模型目录、价格、过滤词和 CLI | 明确拒绝 | 与当前 Provider 不同且易过期；实时能力目录、请求快照和本地账本是唯一事实来源 |
| Shuohao 独立 HTML 报告与 Higgsfield 记忆数据库 | 明确拒绝 | Studio 和项目内请求、任务、提示词、资产账本已覆盖，复制会形成第二事实来源 |
| 每个工具的可执行自检 | 已吸收为集中入口 | 保留现有最小自检，由 `integration-self-check.mjs --self-check` 统一执行，不复制一套测试框架 |
| 营销工作室、无限画布和平台专属应用 | 范围外 | 不属于“本地素材到本地短剧成片”的标准制作链 |

### 三轮专业知识审计

| 专业面 | 已吸收或纠正 | 明确边界 |
|---|---|---|
| 场景导演 | 从场尾关系/信息变化反读共同事件；每名在场角色以各自动机、目标、策略和身体通道参与 | 不把主题或观众效果写成演员任务，不补造来源动作 |
| 表演指导 | 沉默听者也有判断、隐瞒、等待或维持局面的任务；困难回答先判断再开口，持续体力状态不跨镜重置 | 不照搬 FACS/AU 编码，不把无证据微动作固化成表演 |
| 调度与关系 | 接近、退让、占据空间和地位翻转必须对应节拍；三人以上锁人数、左右顺序、朝向和肢体归属 | 不使用模型无法稳定兑现的精确米数，不把群体全貌、双人戏和手部交互塞进一镜 |
| 摄影与焦点 | 由叙事焦点和关系决定单人清晰、多人共同清晰或拉焦；特写默认固定但可为动作/揭示而移动 | 删除“景别自动决定景深”“所有对白只允许说话者清晰”等伪硬规则，设备数字不能代替可见结果 |
| 镜头语言 | 镜头运动响应主体动作、信息权力和场级视点；逐列检查景别、机位、运动与覆盖单调 | 删除 80%、70/30、连续三镜等无普适依据比例，不机械远—中—近或套用荷兰角/环绕 |
| 视觉层级与美术 | 每镜一个首要可读信息；光源必须有场景动机；角色具备远景可认的轮廓身份；强调色绑定剧情对象 | 不用随机霓虹、烟雾、轮廓光或乌鸦/时钟等通用象征制造“电影感”，单色方案不强造强调色 |
| 参考帧与物理生成 | 首帧缺关键元素时补分镜或绑定资产；接触动作写前/中/后状态、邻接不变量和稳定完成态 | 仅明确画外进入时允许首帧缺席，不让模型暗中发明元素位置 |
| 动作与连续性 | 防动作倒放/回弹；步行保持落脚、重心、方向和同行位置；跨镜打斗用尾帧接首帧并在运动中切接 | 精细步态只在剧情需要时写，不把经验性物理提示升级为所有镜头固定词串 |
| 对白与屏幕 | 允许有动机的画外对白；多人对白按 Provider 能力、非重叠时段和嘴部状态决定；精确 UI 交后期 | 不再强制所有说话者入画，不让视频模型随机生成屏幕文字或界面 |

复审继续清理了会覆盖正文规则的旧示例：摄影示例不再把特写绑定极浅景深或要求每镜填写 T 值，表演示例不再用堆叠微动作暗示“越多越专业”，接触微震改为事件同步而不是模型难以兑现的固定帧数。复杂打斗在缺少可信运动参考时改写为身体位置、蓄力、接触、受力结果和反应；只有参考能约束轨迹时才保留精确招式。

再次复审补齐离画人物的连续性：导演台账记录离画边、最后姿态、运动方向和持物状态，分镜转场合同把状态保留到下一次入画，视频提示词不得任意选择回场方向，审片核对是否从错误一侧返回。未引入独立试镜流程；当前角色图候选、逐镜表演合同和付费前确认已覆盖标准制作，只有项目出现可复现的“静态角色正确但入戏表演持续失败”时才值得增加低成本动态试演阶段。

## 验证口径

`node scripts/audit-plugin.mjs` 必须同时验证 Skill 归属、全部中英文模板、变量对称、系统变量注入、无未替换变量、项目规范、Seedance/H3 专属合同、UI 元数据和原系统字段隔离。`node scripts/integration-self-check.mjs --self-check` 必须先执行全部脚本与 Provider 合同自检，再跑通九阶段门禁、来源归档、并发任务账本、资产 provenance 与选版、视频提示词版本、逐镜验收、时间线、完整审片、交付 manifest 和全项目校验；插件与每个 Skill 必须通过官方结构校验。
