# 短剧市场调研与题材分析设计

日期：2026-09-16

状态：用户已确认
目标版本：0.8.0

## 1. 产品目标

在短剧工厂中新增全局“市场调研”能力，基于剧查查 8 类公开排行榜生成可追溯的题材分析、竞争格局和决策报表。该能力服务立项前判断，不依附单个项目，但报告可以作为后续创作简报的外部证据输入。

成功标准：

1. 用户能在 Studio 全局入口手动拉取最新榜单，并看到来源、时间、样本量和覆盖限制。
2. Skill、CLI 和 Studio 使用同一套采集、归一化、分析与存储逻辑。
3. 每个题材结论都能下钻到原始作品和榜单，不生成无数据支撑的市场事实。
4. 连续保存两个以上快照后能够比较趋势；只有一个快照时明确显示证据不足。
5. 采集失败不覆盖上一次成功快照，不保存 Cookie、登录令牌或微信状态。

## 2. 范围与非目标

### 2.1 本期范围

- 热力榜、动态漫榜、真人 AI 榜、沙雕漫榜、抖音热播榜、快手热播榜、红果榜、短剧收入榜。
- 每类榜单公开 Top 30 数据的手动刷新与全局快照。
- 题材、受众、时代、表现形式、平台、公司角色、热度、新剧和霸榜时长归一化。
- 题材热度、增长、新剧势能、跨平台性、拥挤度、头部集中度和机会评分。
- 当前快照、历史趋势、平台交叉矩阵、公司集中度和作品证据下钻。
- JSON 与 Markdown 报告，以及 Studio 全局市场调研页面。
- 可选地把报告路径登记到具体项目，但不自动修改项目创作字段。

### 2.2 非目标

- 不绕过登录、付费、验证码、访问配额或公开 Top 30 限制。
- 不在后台定时轮询，不做无人值守采集。
- 不把榜单表现直接等同于投资回报、真实流水或最终选题结论。
- 不调用外部文本模型生成市场事实；Codex 只解释已保存的数据证据。
- 不在首期建设账号体系、多人协作、云同步或远端数据库。

## 3. 用户与核心任务

| 用户 | 高频任务 | 成功标准 |
| --- | --- | --- |
| 制片人/策划 | 判断近期值得关注的题材 | 看到机会、风险、证据作品和置信度 |
| 编剧/导演 | 理解题材组合与表现形式 | 找到平台差异、受众倾向和可借鉴结构 |
| 投放/运营 | 比较平台热度与新剧增长 | 能按榜单、平台、题材过滤和下钻 |
| Codex Agent | 为创作简报提供市场证据 | 读取稳定 JSON 合同并输出带引用报告 |

全局市场中心只读展示历史数据；“刷新数据”和“生成报告”是明确的用户动作，需要 CSRF 校验。删除快照不在本期范围。

## 4. 信息架构

Studio 一级导航：

```text
工作台
├── 项目总览
└── 市场调研
    ├── 市场脉搏
    ├── 题材机会
    ├── 平台交叉
    ├── 公司格局
    └── 历史报告
```

全局路由为 `#/market`。项目路由继续使用 `#/projects/<key>/<view>`，两者互不嵌套。市场报告可以显示“用于项目”动作，但只登记报告引用，不改变项目题材。

## 5. 页面布局

### 5.1 首屏

- 左侧沿用 Studio 导航，增加“市场调研”入口。
- 顶部显示页面标题、最近成功采集时间、数据覆盖说明和“刷新数据”按钮。
- 过滤条提供榜单、周期、题材、受众和表现形式；筛选只作用于当前分析视图，不改写快照。
- 四个核心指标横向排列：样本作品、覆盖榜单、上升题材、集中度风险。
- 主区域采用 8:4 分栏：左侧题材机会矩阵与题材排行，右侧为决策摘要和证据不足提示。

### 5.2 下钻区

- 题材排行：可按机会分、热度、增长、供给量排序。
- 平台交叉：题材 × 榜单热度矩阵，显示覆盖强弱和样本数。
- 公司格局：版权方、平台方、承制方分别计算 Top 3 集中度。
- 新剧观察：只展示服务端明确标记为新剧的作品。
- 历史趋势：至少两个可比快照才绘制变化；否则显示采集下一期数据的提示。
- 证据抽屉：点击题材后列出作品名、榜单、排名、热度字段、标签来源和采集时间。

### 5.3 状态设计

| 状态 | 界面行为 |
| --- | --- |
| 首次进入 | 解释数据来源和 Top 30 限制，提供“获取首份数据”主按钮 |
| 刷新中 | 使用与最终布局一致的骨架，按钮禁用并显示当前阶段 |
| 部分成功 | 保存成功榜单并列出失败榜单；报告标记覆盖不完整 |
| 全部失败 | 保留上次成功结果，展示可重试错误，不创建空快照 |
| 单快照 | 当前横截面可用，趋势模块显示证据不足 |
| 多快照 | 显示同周期、同榜单口径的变化 |
| 无筛选结果 | 保留筛选条件并提供清除筛选动作 |
| 数据过期 | 超过 24 小时显示“数据可能已更新”，不自动联网 |

## 6. 视觉与交互系统

- 产品类型：高密度数据智能工作台。
- 平台：桌面优先，宽度小于 900px 时转单列；375px 保证无水平溢出。
- 色彩：延续 Studio 中性深灰，唯一强调色沿用现有橙红；成功、警告、错误只用于状态。
- 排版：普通文本沿用系统无衬线；指标数字使用等宽数字特性。
- 间距：8px 基础节奏；面板使用 12px 圆角；筛选胶囊仅用于交互控件。
- 图表：不引入第三方图表库，使用语义 HTML、CSS 条形和可访问表格；所有图形都有文字摘要。
- 动效：150–220ms，仅用于筛选、抽屉和状态切换，并尊重 `prefers-reduced-motion`。
- 可访问性：正文对比度至少 4.5:1，焦点可见，按钮有明确文字，错误不只依赖颜色。

## 7. 共享架构

```text
scripts/market/juchacha-client.mjs
  → scripts/market/normalize.mjs
  → scripts/market/analyze.mjs
  → scripts/market/store.mjs
  → scripts/market-research.mjs
        ├── skills/analyze-drama-market/SKILL.md
        └── scripts/studio.mjs → studio/app.js
```

责任边界：

- `juchacha-client.mjs`：协议签名、超时、错误信封、8 类榜单和日期选择。
- `normalize.mjs`：把榜单差异转成统一作品结构，保留 `rawRef`，不做业务评分。
- `analyze.mjs`：纯函数计算指标和报告，不联网、不写文件。
- `store.mjs`：路径约束、原子写入、索引和历史读取。
- `market-research.mjs`：CLI 编排 `refresh`、`analyze`、`report`、`list`。
- Studio API：调用共享模块，不复制签名或评分公式。

## 8. 数据存储合同

全局目录：

```text
<workspace>/.short-drama-market/
├── index.json
├── snapshots/<snapshot-id>.json
└── reports/
    ├── <report-id>.json
    └── <report-id>.md
```

`snapshot.v1`：

```json
{
  "schema_version": 1,
  "snapshot_id": "20260916T153000+0800",
  "retrieved_at": "2026-09-16T15:30:00+08:00",
  "source": { "provider": "dataeye-juchacha", "coverage": "public-top-30" },
  "rankings": {},
  "failures": []
}
```

`market-report.v1` 顶层字段固定为：

- `schema_version`
- `report_id`
- `generated_at`
- `snapshot_ids`
- `coverage`
- `filters`
- `summary`
- `topic_metrics`
- `platform_matrix`
- `company_concentration`
- `new_title_watch`
- `evidence`
- `limitations`

原始接口响应只保存在快照中；报告使用 `snapshot_id + ranking_type + playlet_id` 引用证据，避免复制不可控的大对象。

## 9. 归一化合同

统一作品对象：

```js
{
  key, playletId, title, rankingType, ranking, observedAt,
  topics, audience, era, format,
  heatValue, growthValue, isNew, persistenceDays,
  companies: { platform, contractor, copyrightHolder, producer },
  provenance: { topicSource, rawRef }
}
```

规则：

1. 优先使用接口明确提供的 `playletTags` 或 `tags`。
2. 字符串化 JSON 必须安全解析；`null`、空串和无意义标签被移除。
3. 没有标签时可以用 `genre-guide.md` 的受控关键词从标题推断，但必须标记 `topicSource: title-keyword` 和低置信度。
4. 同一作品跨榜单保留多条观察记录，在分析层按 `playletId` 合并。
5. 热度字段按榜单保留原始量纲，跨榜单比较使用榜内百分位而不是直接比较绝对值。

## 10. 分析模型

每个题材计算：

- `supply_count`：去重作品数。
- `rank_strength`：榜内排名百分位均值。
- `demand_strength`：热度字段的榜内稳健百分位。
- `growth_strength`：增量字段的榜内稳健百分位。
- `new_title_rate`：明确新剧数 ÷ 题材作品数。
- `platform_coverage`：覆盖榜单数 ÷ 当前成功榜单数。
- `persistence_strength`：霸榜天数的截尾归一化均值。
- `crowding`：题材作品数占全部去重作品比例。

机会分采用透明公式：

```text
opportunity = 100 × clamp(
  0.28 × demand_strength
  + 0.22 × growth_strength
  + 0.16 × new_title_rate
  + 0.18 × platform_coverage
  + 0.16 × persistence_strength
  - 0.20 × crowding,
  0,
  1
)
```

置信度由样本量、成功榜单覆盖和标签来源构成，分为 `high`、`medium`、`low`。机会分是筛选指标，不是投资承诺；报告必须同时展示拥挤度、样本数和限制。

## 11. Skill 设计

新增 `analyze-drama-market`：

- 触发：用户询问近期短剧题材趋势、平台榜单、市场机会、竞争格局或要求市场报告。
- 不触发：分析单部小说或剧本内容、写单集剧本、投放预算预测、绕过付费获取榜单。
- 默认流程：检查工作区 → 使用最新快照或经用户动作刷新 → 生成报告 → 核对覆盖与置信度 → 输出结论和报告路径。
- 输出顺序：事实摘要、题材机会、竞争风险、平台差异、新剧观察、创作启示、证据限制。
- 所有定量结论引用 `report_id` 和证据条目；不把标题关键词推断写成确定事实。

Skill 附带 `market-report.schema.json`，并在 `short-drama-skill-index` 中登记。`define-drama-brief` 只在用户明确要求“参考市场报告”时读取指定报告。

## 12. Studio API

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/v1/market` | 返回最新报告、快照摘要、历史列表和数据状态 |
| POST | `/api/v1/market/refresh` | 手动采集并生成报告，需要 CSRF |
| GET | `/api/v1/market/reports/:id` | 返回指定 JSON 报告 |
| GET | `/api/v1/market/reports/:id/markdown` | 返回 Markdown 报告文本 |

刷新操作设进程内互斥锁，重复提交返回 409。网络失败映射为 502，响应不包含上游请求头或内部堆栈。所有 ID 先通过白名单正则，再解析到受控目录。

## 13. 测试与验收

- 协议固定签名、8 类端点、超时和业务错误测试。
- 归一化覆盖每类榜单字段、脏标签、字符串 JSON 和缺失字段。
- 分析公式、百分位、跨平台去重、置信度和单快照限制测试。
- 存储路径穿越、原子写入、部分成功和索引恢复测试。
- Studio API 的 GET、CSRF、并发锁、502 和静态资源测试。
- 路由刷新恢复、首次空态、加载态、错误态、筛选和证据抽屉测试。
- 真实烟测只请求公开 Top 30，作为显式命令，不进入离线单测。
- 最终运行 `node scripts/audit-plugin.mjs --self-check`、`node scripts/integration-self-check.mjs --self-check` 和三清单版本一致性检查。

## 14. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 第三方接口字段变化 | 响应形状校验、部分失败记录、原始快照保留 |
| Top 30 样本偏差 | 页面和报告持续展示覆盖限制 |
| 不同榜单量纲不可比 | 使用榜内百分位，不直接相加原始数值 |
| 单次快照误判趋势 | 至少两个同口径快照才输出趋势 |
| 标题推断题材误判 | 低置信度和来源标记，可在证据抽屉核对 |
| 远端失败破坏现有结果 | 新快照成功落盘后才更新索引 |
| 报告被误当投资建议 | 展示方法、样本和限制，不输出收益承诺 |
