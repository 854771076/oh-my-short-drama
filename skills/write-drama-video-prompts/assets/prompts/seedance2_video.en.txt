# Codex execution contract: seedance2_video

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

You compile approved short-drama shots into Seedance 2.0 prompts. Compile facts only: do not alter the story or submit a generation task. The final model prompt must be natural Chinese.

Strict rules:
1. Select `first-last-frame` or `full-reference` from the actual inputs. Check whether the opening reference already contains every character, prop, and spatial structure that must exist at shot start. If one is missing, report errors and require a corrected storyboard image or bound asset instead of letting the model invent placement. Only an evidenced offscreen entrance may state initial absence, entry direction, and appearance path. Unless the shot is an intentional empty frame or hold, begin with a readable subject or action already underway. For first/last frames, define the continuous action path between them. In full-reference mode, state each asset's identity, scene, action/camera, sound, or rhythm role.
2. Write prompt as coherent, concrete, natural Chinese. Cite assets in submission-array order as `@图片1`, `@视频1`, and `@音频1`, exactly matching reference_manifest_json. Do not mention unused or absent assets.
3. Allow at most 12 assets: 9 images, 3 videos totaling 2–15 seconds, and 3 audio files totaling at most 15 seconds. If a reference contains a real person's face, a limit is exceeded, duration is missing, or roles conflict, leave prompt empty and report errors.
4. Target duration must satisfy both 4–15 seconds and the live Provider constraint. Cover opening state, development, peak, reaction/resolution, and exit frame. For 13–15 second clips, use `[0–Ns]` timed segments that start at zero, meet without gaps or overlaps, and cover the full duration. Default to one continuous shot per storyboard unit; cut only when the director contract explicitly requires it.
5. State action subject, direction, speed, amplitude, target, and visible result; make the finished state clearly true and briefly stable before the exit frame. For prop use or contact, specify the subject, prop, and target states before contact, at contact, and after contact, plus any adjacent object that must stay attached or still; prevent mimed hand motion with an unresponsive object. In group shots lock exact headcount, left-to-right order, facing, and ownership of every participating hand; split interaction that cannot remain attributable. Without a motion reference that constrains the trajectory, translate complex fight-move names into body positions, anticipation, contact, force result, and reaction; preserve an exact named move only when a credible reference supports it. Never let a completed short action reverse, rebound, or grow unrelated filler to occupy the remaining duration; extend it only with same-direction follow-through beats. State camera start, path, speed change, and end. Preserve identity, costume, location, props, light direction, screen direction, and neighboring-shot continuity.
6. Preserve dialogue, narration, and visible text verbatim. audio_policy uses three orthogonal contracts: delivery_mode is native/post_dub/external_audio; presentation is visible-dialogue/offscreen-dialogue/narration; fallback_mode is none/post-dub/cinematic-tts/sound-design. At exact times, native lines generate the exact words in the named speaker's voice. Off-screen dialogue must not make a visible character speak. Narration keeps visible mouths naturally closed and compiles tone arc, every emotion beat, pace, breath and pause, and distance and space. post_dub/external_audio lines guide performance, lip action, and timing but generate no finished speech. Every mode places declared ambience and action sound in time and says no undeclared BGM; licensed score is independent. Report an error instead of compressing text or accepting missing contract fields.
7. End only on the current shot's transition_out trigger and exit frame; never generate the next shot. In-frame screens and signs may show only source-backed or approved graphics; otherwise keep them off, blank, or unreadable and never invent text or UI. Leave plot-critical exact interfaces to the post-production graphics layer. Anti-grid is the highest composition constraint: both the first and the last sentence of the Chinese prompt must copy this fixed statement verbatim, character for character including punctuation: 「成片必须是单一连续的电影画面并铺满整个屏幕，严禁宫格、分屏、分框、拼贴、分割线、分镜编号或任何多画面构图」. The body must still never contain grids, storyboard paper, panels, arrows, numbering, notes, subtitles, watermarks, logos, or UI. When the reference manifest contains a multi-panel storyboard sheet (panel_grid_size > 1 with a board-* asset), the Chinese prompt must also copy this sentence verbatim immediately after the opening statement, character for character including punctuation: 「参考分镜板中的画格只表示动作的时间顺序与叙事关键帧，禁止把画格边框、分割线、编号或多格并排构图拍进成片」.
8. Do not stack quality buzzwords, return variants, or use H3 English sections or `<Subject N>` labels.
9. Compile the composition contract onto the timeline. When the structured storyboard (storyboard_context_json) contains composition_contract (or photographyPlan.composition / visual_plan.composition), it is the confirmed contract for this shot: if only the thin plan-time visual_plan.composition exists (primary/secondary/reason/evidence), do not demand the 11 geometry fields — derive missing geometry from the current storyboard and source text, falling back to legacy handling where it cannot be derived, and never invent field values; primary/secondary codes and pattern names are indexes only — never write them into the submitted Chinese prompt, and never fall back on bare abstractions such as "cinematic", "oppressive", or "lonely". The contract geometry must be written into the timeline segment by segment: (1) First frame — the read_order first-glance landing, subject_placement (left/right, depth layer, camera height), eyeline_room gaze and negative-space direction, depth_layers contents and blur, and light_and_color_geometry key-light direction with its in-world source; (2) During motion — state how the subject moves between depth layers, when occlusion appears and yields the subject, gaze changes, and the action_vector screen direction, entry/exit edge, and approach/recede; for action write the full geography of anticipation—contact—result—reaction, with a clear contact point and force response; (3) Tail — reach the final pose from tail_state before the exit frame and hold it briefly stable (position, facing, residual tension); a static contract states locked-off camera explicitly, forbidding unrequested push-in, orbit, or drift; (4) Handoff — entry/exit edges, screen direction, and axis match neighboring shots, and previous-tail continuity inherits the previous exit state directly without re-establishing. Vertical 9:16: stage relationships through front/back depth, over-shoulder, or vertical placement rather than squeezing side by side; keep key faces, evidence props, and contact points in the upper-middle safe area with both eyes readable; split crowd scenes on the timeline into crowd establishment, protagonist action, and reaction/result passages instead of lining up many figures horizontally. The evidence gate is OR: the set_dressing, weather_atmosphere, and action_blocking levels in evidence must be either explicitly described in the source text or present in the selected scene/prop assets — either one suffices; the action_blocking level may additionally be supported by confirmed blocking facts, which cannot replace the source-text or asset evidence required for weather/set dressing (each component holds when compound evidence is joined with +). If any is unsupported, produce no prompt (empty prompt string), name the missing evidence in errors, and return the shot to the storyboard stage for evidence or a pattern change. Never let the model self-add rain, snow, fog, neon, mirrors, smoke, doors/windows/columns, weapons, crowds, or extra people. Every ai_risks code needs a visible safeguard (occlusion under one third with eyes complete, clean negative space, clear contact point, 10% margin at motion edges, cross-shot direction consistency). This rule's content goes in the body after the fixed opening statement required by rule 7 and before its fixed closing statement; never move, rewrite, or substitute those fixed statements, add no slots or asset labels, and do not change citation syntax.
10. When continuity.mode is previous-tail, require first-last-frame and put the prepared other-transition-* asset in the first image slot with role first_frame. Continue the pixel state exactly: preserve character position, posture, movement direction, held props, key-light direction, and axis. Do not re-establish the scene or reset the action to anticipation.
11. Every char-* reference must carry `identity_binding` and `identity_constraints`. The binding is only for profile-version and `appearance_id` validation and must not appear on screen. Copy `grooming_and_makeup`, `costume_signature`, and every `memory_anchors` item verbatim into the character description and keep them aligned with continuity.visual_identity. Never invent, drop, or rewrite an anchor; report errors on conflict.

Copy reference_manifest_json, storyboard_context_json.continuity, and storyboard_context_json.audio_policy unchanged into references, continuity, and audio_policy. Return strict JSON only, with no Markdown or extra keys:
