# Codex 执行合同：seedance2_video

严格规则：
1. 根据真实输入选择 `first-last-frame` 或 `full-reference`，不可把素材存在等同于已引用。逐项核对首帧是否已有本镜开场就应存在的人物、道具和空间结构；缺失时返回 errors，要求补分镜图或绑定资产，不让模型暗中发明位置。只有剧情明确要求元素从画外进入时，才写明首帧缺席、进入方向和出现路径。除有意空镜或 hold 外，首帧应已有可读主体或动作起势。仅首尾帧时明确第一帧和最后一帧间的连续动作路径；全参考时逐项说明身份、场景、动作/运镜、声音或节奏用途。
2. prompt 必须是连贯、自然、具体的中文。引用按提交数组顺序写作 `@图片1`、`@视频1`、`@音频1`，编号、类型和用途必须与 reference_manifest_json 一致；未实际使用的素材不写标签，无素材不造标签。
3. 素材总数≤12：图片≤9，视频≤3且总时长2–15秒，音频≤3且总时长≤15秒。发现真实人物脸部参考、超量、缺时长或用途冲突时，不生成 prompt，把问题写入 errors。
4. 目标时长必须在4–15秒及 Provider 实时约束内。用完整时间轴覆盖起始状态、动作发展、峰值、反应/收束和镜尾；13–15秒必须使用 `[0–Ns]` 格式分段，所有时间段从 0 开始、首尾相接并覆盖完整时长。默认一个分镜单元生成一个连续镜头，只有导演本明确要求内部切镜时才写切点。
5. 动作写出主体、方向、速度、幅度、作用对象和可见结果，结果必须在镜尾前清晰成立并短暂稳定；涉及道具或接触时，分别写清接触前、接触点和接触后主体、道具、目标的状态，以及必须保持连接或静止的邻接物，防止只生成手势而物体不响应。多人镜锁定准确人数、从左到右顺序、朝向及参与动作的手属于谁；无法清楚归属的复杂交互拆镜。复杂打斗缺少能约束运动轨迹的参考时，不用招式名称代替编排，改写为双方身体位置、蓄力、接触点、受力结果和反应；有可信运动参考时才保留精确招式。短动作不得在完成后自动倒放、回弹或用无关动作填满剩余时长；需要延续时拆成同方向的后续节拍。运镜写出起点、路径、速度变化和终点。保持人物身份、服装、场景、道具、光向、运动轴线和前后镜状态连续。
6. 对白、旁白和画内文字逐字保留原文。按 audio_policy 执行：native 才生成对应人声；post-dub 只用台词指导口型和节奏；silent 不生成声音；auto 只写必要声音意图。声音放不下时返回 errors，不压缩或改写台词。
7. 末尾只形成当前镜 transition_out 所需的触发与结束画面，不生成下一镜剧情。画内屏幕或招牌内容只能来自原文或已批准图形合同；无证据时保持关闭、空白或不可辨读，不生成随机文字和 UI。剧情依赖的精确界面留给后期图形层。反宫格是最高构图约束：prompt 的首句和末句都必须原样写入以下固定声明（一字不改，标点也不改）：「成片必须是单一连续的电影画面并铺满整个屏幕，严禁宫格、分屏、分框、拼贴、分割线、分镜编号或任何多画面构图」；正文任何位置仍不得出现宫格、故事板纸张、分框、箭头、编号、批注、字幕、水印、Logo 或 UI。当引用清单含多格分镜板（panel_grid_size>1 且引用 board-* 资产）时，紧接首句声明之后还必须原样写入（一字不改，标点也不改）：「参考分镜板中的画格只表示动作的时间顺序与叙事关键帧，禁止把画格边框、分割线、编号或多格并排构图拍进成片」。
8. 不堆砌画质词，不输出多个候选版本，不使用英文 H3 字段或 `<Subject N>` 标签。
9. 构图契约必须编译进时间轴。结构化分镜 storyboard_context_json 中若出现 composition_contract（或 photographyPlan.composition、visual_plan.composition），它是本镜已确认构图合同：若仅有 plan 期瘦合同 visual_plan.composition（只含 primary/secondary/reason/evidence），不要求 11 个几何字段齐全，缺失几何从当前分镜与原文推断、推断不出按旧分镜回退，不编造字段值；primary/secondary 的 code 与构图模式名仅作索引，禁止写进提交给模型的中文 prompt，也禁止只交「电影感」「压迫」「孤独」等抽象形容词，必须把合同几何逐段写入时间轴：① 首帧——read_order 的第一眼落点、subject_placement 的画面左右/前后景/机位高度、eyeline_room 的视线与留白方向、depth_layers 前中后景内容与虚实、light_and_color_geometry 的主光方向与剧内来源；② 运动中——写清主体在层次间的位移、遮挡何时出现与让出、视线变化，以及 action_vector 的屏幕方向、入画/出画边、逼近或远离；动作镜按蓄力—接触—结果—反应写全地理、接触点与受力反应；③ 镜尾——按 tail_state 在结束画面之前到达终结姿态并短暂稳定（位置、朝向、剩余张力），静止合同显式写固定机位（locked-off），禁止未要求的缓推、环绕、漂浮；④ 承接——出入画边、屏幕方向与轴线和相邻镜一致，continuity 为 previous-tail 时逐项精确继承前镜尾部的人物位置、姿态、运动方向、持物状态、主光方向与轴线，不得重新建立场景或把动作重置为起势。竖屏 9:16：关系镜用前后纵深、越肩或上下站位而非硬挤左右；关键脸、证据道具、接触点放在画面中上安全区且双眼完整可读；群体戏在时间轴拆为群体建立、主角动作、反应/结果等段落，不横向平铺多人。证据门为 OR：evidence 中的 set_dressing、weather_atmosphere、action_blocking 等级必须在原文明确描述或已选场景/道具资产中存在，二者任一即可；action_blocking 等级还可由已确认动作事实支撑，已确认动作事实不能替代天气/陈设所需的原文或资产证据（复合证据以 + 连接时逐组件成立）。任一不满足时不生成 prompt（prompt 置空字符串），在 errors 写明所缺证据并退回分镜阶段补证据或更换构图，禁止让模型自补雨、雪、雾、霓虹、镜面、烟尘、门窗廊柱、武器、群体或多余人物。ai_risks 每个风险码都要有可见防控（遮挡不超过三分之一且双眼完整、留白区纯净、接触点清晰、动势边缘留 10%、跨镜方向一致）。本条内容写在第 7 条固定首句声明之后、末句固定声明之前的正文里，不得移动、改写或替换固定声明，不新增槽位、素材标签，也不改变引用语法。

输出中的 references、continuity、audio_policy 必须分别原样复制 reference_manifest_json、storyboard_context_json.continuity 和 storyboard_context_json.audio_policy。只输出严格 JSON，不要 Markdown 或额外键：

  "errors": []
}
