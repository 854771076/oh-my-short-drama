# 武器、灰模与术法预设

只在镜头确有兵器、关键道具或超自然动作时读取。预设服务空间、动作和接触验证，不追求最终美术质量。

## 选择顺序

- 普通场景物：门、墙、桌、台阶、箱体优先组合 `cube`；柱、瓶、树干优先 `cylinder`；球形关键物优先 `sphere`。只在轮廓会改变调度或遮挡判断时增加细节。
- 常见兵器：直剑用 `sword`，单刃挥砍用 `dao`，长距离突刺用 `spear`，无刃长兵器用 `staff`，防御面积验证用 `shield`。不要用不同名称复制同一几何体。
- 修仙术法：蓄力/飞行物用 `orb`，持续直线能量用 `beam`，范围冲击边界用 `ring`，碰撞或破裂瞬间用 `burst`。复杂烟火留给最终 VFX，不在白模阶段堆粒子。

## 编导约束

- 兵器用 `attach_to` 绑定 `left_hand` 或 `right_hand`；持握偏移先在低清预览校准，再锁定合同。双手兵器若没有双手 IK，只能测试单手主控轨迹，合同必须披露该限制。
- 刀剑挥砍检查尖端弧线和刃侧朝向；枪棍检查杆身是否穿体、前手引导与后手发力；盾检查盾面是否覆盖攻击线。每次真实碰撞写 `contact_checks`，对象端按碰撞位置使用 `point=origin`、`mid` 或 `tip`。
- 术法至少保留施法者身体动作、特效生成点、可跟踪轨迹、碰撞/闪避点、对方反应和消散。强光不能遮住人物轮廓与接触点；同镜不同阵营使用稳定的冷暖色区分。
- 发光预设使用 Eevee 发射材质和低质量 Fog Glow，只用于动作可读性。需要烟雾、流体、布料、破碎或精确法术形态时，白模标记能力缺口并移交最终特效流程。

## 审计补充

- 持握：柄与手同动，无明显脱手、穿掌或反向握持。
- 轨迹：起点、攻击线、接触点、回收方向连续；长兵器不穿过持有者或镜头。
- 术法：颜色能辨归属，运动方向与施法动作一致，碰撞后有结果，粒子不替代剧情动作。
- 技术：记录合同生成、首帧/预览、完整渲染和审计耗时；重跑时分别记录，不用累计值冒充单次制作时间。
