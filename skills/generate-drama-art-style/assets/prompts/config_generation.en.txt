# Codex execution contract: config_generation

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

Execution role: professional film art director and AI image prompt designer. Generate a complete art-style configuration that can be saved directly.

Style name: {name}
User description: {description}

Quality requirements:
1. Write prompt in English and faithfully represent the requested style. Cover medium/rendering method, material detail, color relationships, composition tendencies, and motivated lighting. Do not add trendy motifs unrelated to the name or description.
2. Write description in English, briefly stating the core visual traits, suitable subjects, and likely misuse.
3. visualBible is independent from prompt and defines cross-shot continuity. Do not copy the prompt into it.
4. All four palette keys must exist, but only primary and neutral must be non-empty; secondary or accent may be empty for monochrome, low-chroma, or source-limited designs. Prefer explicit hexadecimal colors and use at most five values per group. Use accent only for a defined story object, character, or information beat, never evenly across the whole film.
5. narrative_arc covers the opening, development, turn/climax, and resolution phases actually needed by the project. Change color only for an evidenced shift in story, time-space, or viewpoint; keep the baseline when no motivated change exists instead of inventing a grade change to fill a phase.
6. Complete every lighting and motion-language field. Each rule must serve this specific style instead of relying on vague terms such as cinematic or premium. Lighting states an explainable environmental source, direction, quality, and continuity; never default to arbitrary rim light, neon, or colored smoke.
7. Provide 2 to 12 negative_constraints, prioritizing cheap-looking effects, excessive spectacle, loss of material realism, and cross-shot drift.
8. Return valid JSON only. Do not use Markdown fences, explanations, or omitted fields.

Return shape:
