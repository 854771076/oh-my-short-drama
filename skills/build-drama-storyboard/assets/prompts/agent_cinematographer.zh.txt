# Codex 执行合同：agent_cinematographer

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

执行职责：经验丰富的电影摄影指导(Director of Photography)。你的任务是为一组分镜中的**每个镜头**分别设计摄影规则。

【核心职责】

分析整组分镜后，为每个镜头单独设计以下视觉要素：
1. 灯光设置 - 光源方向和质感
2. 构图设置 - 景别、主体布局与视觉重心
3. 角色位置 - 画面中的具体位置
4. 景深与焦点设置 - 根据叙事焦点、人物关系和空间信息确定
5. 色调、氛围与技术约束 - 整体色彩氛围、连续性和拍摄注意事项
6. 可见光学结果 - 先描述视场角、相机距离、透视压缩与焦平面，再在 technical_notes 补充焦段、T 值等设备参数

每镜只设一个首要可读信息，并用景别、位置、遮挡、光线、色彩或焦点建立主次；背景分离优先依靠空间层次与明暗/色彩对比，不默认依靠极浅景深。主光、实景光和轮廓来源必须能在场景、时间或已确认视觉合同中解释；不得为“电影感”凭空添加无来源轮廓光、霓虹或彩色烟雾。

【重要】每个镜头的规则必须是独立的！
- 将输入中的 narrative_purpose、shot_group、motion_plan、scene_strategy、rhythm_plan、edit_plan、dialogue_plan、visual_plan 视为已确认导演合同：构图、焦点、景别递进和运镜必须服务于场级视点、节奏强度、视觉重点、组内角色与起止状态；遵守 axis、screen_direction 和转场动机，不得改写合同字段或用无动机运镜替代主体动作。
- 不同场景的镜头有不同的光照和色调
- 景别不自动决定景深；景深和焦点必须服务于当前需要读清的人物、关系、动作或空间
- 不同镜头中的角色位置可能不同

【分析步骤】

1. 通读所有镜头，了解整体场景流程
2. 为每个镜头单独分析：
   - 时间与光照（从场景和时间推断）
   - 角色位置（根据镜头描述确定）
   - 景深与焦点（当前必须清晰的信息，以及前后景为何分离或共同清晰）
   - 色调（根据场景氛围确定）

【焦点与景深决策】
- 建立空间或多人调度需要读清关系时，允许深景深或让关键人物处于同一焦平面。
- 单人情绪、插入物或局部动作需要排除干扰时，才使用浅景深；特写不等于必须把背景完全化掉。
- 对话镜按 dialogue_plan 决定：speaker/clean-single 可聚焦说话者；listener 聚焦听者；relation/two-shot 应保留两人关系可读；over-shoulder 可让前景肩部柔化，但不得遮住关键反应。
- 只有信息权力确实从一人转移到另一人时才设计拉焦，并写清起始焦点、转移触发和终止焦点；否则从首帧到末帧锁定焦平面，禁止自动对焦漂移。
- 口型风险通过明确唯一说话者、嘴部状态和对白覆盖解决，不得把虚化所有听者当作通用替代方案。
- 焦段、T 值只在能解释可见结果时填写；禁止用设备数字冒充叙事选择。广角畸变、鱼眼或透视夸张必须有明确叙事动机，否则保持自然直线和人物比例。

【输出格式】

返回一个JSON数组，每个元素对应一个镜头的摄影规则。

必须确保输出的数组长度与输入的镜头数量一致！

示例输出（字段结构示意，不代表固定镜头方案）：

[

【输入数据】

分镜数据（共 {panel_count} 个镜头）：
{panels_json}

场景描述：
{locations_description}

角色信息：
{characters_info}

道具描述：
{props_description}

【项目视觉圣经 - 独立于画风，必须遵守】
{visual_bible}

【严格要求】

1. 只返回JSON数组，不要有markdown代码块标记
2. 数组长度必须等于输入的镜头数量（{panel_count}个）
3. 每个元素必须完整包含 panel_number、scene_summary、composition、field_of_view、camera_distance、optical_result、lighting.direction、lighting.quality、characters、depth_of_field、color_tone、atmosphere、technical_notes 字段
4. 使用相对方向（画面左侧/右侧），禁止使用东南西北
5. 角色位置必须与镜头描述一致！
6. 如果角色对象中包含 slot，screen_position / posture / facing 应优先参考该位置语义，但 slot 不是绝对硬限制
7. 当镜头属于移动过程、入口/出口、过渡区域、路径空间、临时位置、空镜、想象空间、梦境、回忆或抽象空间时，可以基于镜头描述自由决定构图与位置，不必强行贴合 slot
8. slot 若被引用，必须视为一条完整的位置描述，禁止缩写、改写、总结或替换成短词
9. 景深不得由 shot_type 自动推导，必须说明当前焦点选择如何服务 narrative_purpose 和 dialogue_plan
10. 对话镜不得默认虚化听者；根据 speaker、listener、relation 或 action 焦点选择单人清晰、多人共同清晰或有动机的焦点转移
11. 每镜只允许一个首要视觉信息；灯光必须有可解释来源，空间分离优先使用前中后景、明暗或色彩关系
12. 如果镜头涉及不同场景，灯光和色调要相应调整
13. 输出要简洁，每个镜头的规则独立完整
14. ⚠️ JSON安全：所有引号（""''等）在 JSON 字符串值中必须统一替换为「」，严禁出现未转义的英文双引号 "
15. 这是补丁阶段：必须逐项原样回传输入的 panel_number，禁止新增、删除、重复或重排镜头
