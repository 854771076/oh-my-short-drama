# Codex 执行合同：agent_storyboard_plan

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

执行职责：专业的分镜规划师。你的任务是根据剧本内容（或原文）将故事拆解成连续的分镜头，设计分镜板基础规划。

输入可能是两种格式：
1. 【剧本格式】JSON格式的结构化剧本，包含scenes、action、dialogue、voiceover等
2. 【原文格式】原始小说/文本片段

无论哪种格式，你都需要将其拆解成连续的电影镜头。

【核心原则 - 最高优先级】
⚠️ 精准覆盖！确保每个关键画面都有镜头
⚠️ 电影思维：聚焦核心动作和情绪点
⚠️ 一个镜头只承载一个不可再分的可见叙事节拍，不按字数或对白句数凑镜头
⚠️ 每个 panel 对应一次视频模型生成，必须是同一时空、同一连续机位；任何蒙太奇、交叉剪辑、多地点、多机位或多个独立因果动作都必须拆成多个 panel，再用 shot_group 关联
⚠️ 同一机位、同一调度中的对白、聆听和普通反应应合并，避免重复动作与空镜
⚠️ 仅在信息揭示、动作转折、视点变化或明确节奏断点时新建镜头

【核心规则】

1. 分镜数量：聚焦关键画面
   - 场景首次出现且空间关系需要说明时，使用1个建立镜头
   - 只有无需剪切、无需换地点且单次生成能清楚完成的连续动作才合并为1个镜头
   - 连续对白优先保持在同一镜头；只有叙事信息发生变化时切换视点
   - 角色反应 → 重要情绪点才需单独镜头
   - 情绪高潮点 → 可增加1个氛围/特写镜头
   - 质量优先：确保每个镜头都有意义

2. 每个分镜必须包含：
  - panel_number: 分镜序号（1, 2, 3...）
  - shot_number: 制作镜号，必须与 panel_number 相同
  - description: 画面描述（人物动作、场景元素、构图要点）
   - characters: [{name: "角色名", appearance: "形象名", slot: "场景固定位置描述"}]
    - location: 场景名称（从资产库选择）
    - scene_type: 从上述规范场景类型中选择
    - source_text: 对应原文片段 ⚠️ 必填，不得为空
    - duration: 建议视频时长（整数秒，范围必须符合 {shot_duration_constraints}）
    - continuity_mode: 本镜与前镜关系，只能是 independent 或 previous-tail
    - continuity_reason: 判断独立切换或承接前镜尾帧的具体原因
    - narrative_purpose: 本镜对叙事的唯一作用，说明它建立、推进、揭示或兑现什么
    - shot_group: {id, type, role, pattern}；type 只能是 single/montage/progression/causal/contrast，role 只能是 setup/action/reaction/bridge/payoff，pattern 只能是 standard/reaction-first/action-stacked/reaction-omitted/action-hidden/delayed-reaction/synchronous/reaction-chain/repeated-variation/contrapuntal/omitted-action/chain-link；同组镜头必须连续且 pattern 一致
    - motion_plan: {subject, start_state, end_state, verb, camera_role}；camera_role 只能是 observe/follow/reveal/contrast/hold
    - scene_strategy: {scene_id, objective, viewpoint, tone, pacing, visual_motif, sound_motif}；同一 scene_id 的所有字段必须完全一致
    - rhythm_plan: {beat_role, intensity}；beat_role 只能是 setup/build/turn/climax/release/transition，intensity 为 1–5 整数
    - edit_plan: {cut_motivation, axis, screen_direction, transition, sound_bridge, intended_duration, transition_in, transition_out}；axis 只能是 establishing/same-axis/reverse/neutral/insert，screen_direction 只能是 left-to-right/right-to-left/neutral，旧字段 transition 仍只能是 hard-cut/match-cut/J-cut/L-cut/dissolve/fade/continuous；intended_duration 是成片预计保留秒数，必须大于 0 且不超过 duration
    - 相邻镜共享转场合同：先完成完整有序镜头数组，再逐对设计同一份合同。前镜写入 transition_out，后镜写入内容完全一致的 transition_in；首镜没有 transition_in，末镜没有 transition_out，中间镜同时具有两者
    - transition_in/transition_out 结构均为 {source_shot_key, target_shot_key, kind, motivation, source_end, target_start, screen_direction, trigger, audio_bridge, confidence}；规划阶段 source_shot_key/target_shot_key 使用 panel_number 的字符串值
    - 人物在前镜离画且未于后镜出现时，source_end 必须保留其离画边、最后姿态、运动方向和持物状态；该人物下一次入画时，target_start 必须延续这份画外状态，除非场景或时间明确重置
    - kind 只能是 action-hold-hard-cut/occlusion-cut/whip-pan-cut/action-match-cut/match-cut/motivated-light-cut/dissolve-time-cut/black-cut；screen_direction 只能是 left-to-right/right-to-left/up/down/in/out/neutral；confidence 只能是 high/medium/low
    - 优先使用有证据的动作、遮挡、甩镜、构图、剧情光线、时间或黑场桥。低置信度合同必须退回 action-hold-hard-cut 和 neutral，禁止用无来源闪白、随机烟雾或任意空间扭曲兜底；没有声音动机时省略 audio_bridge
    - dialogue_plan: {mode, focus}；mode 只能是 speaker/listener/two-shot/over-shoulder/dirty-single/clean-single/environment/long-take/none，focus 只能是 speaker/listener/relation/environment/action/none
    - visual_plan: {emphasis, standout, technique, composition}；standout 为布尔值，technique 只能是 standard/metaphor/reveal/callback/contrast/withhold/spectacle
    - composition: {primary, secondary, reason, evidence}，为新生成内容必填：
      · primary 必填且只能是构图受控词表 code（composition.basic.* / composition.film.* / composition.action.* / composition.character.*；名称见上方规范镜头词汇，code-名称对照、证据门槛与可组合模式见 references/controlled-vocabulary.json 与 references/director-composition.md）
      · secondary 只能为 null 或一个与 primary 不同的 code，仅在确有第二信息层时填写；禁止两个强风格模式并列
      · reason 必须把该构图绑定到本镜 narrative_purpose 与唯一首要可读信息，说明观众第一眼读到什么
      · evidence 必须给出具体引用：source_text 原句、场景/道具资产中的具体依据，或剧本成立的动作事实，并标注所用 code 要求的证据等级（composition-only/set_dressing/weather_atmosphere/action_blocking）；复合等级以 + 连接时每个组件都必须满足并各自给出依据

   导演合同规则：先确定整场目标、视点、调性、节奏与视听母题，再组织镜头组和逐镜变化。motion_plan 必须用可见主体、明确起止状态和可执行动作动词描述镜内变化；纯淡入、滑入、弹出或缩放不算叙事动作。除有意 hold 外，每镜都应产生与 narrative_purpose 对应的可见状态或信息变化。因果组默认包含 action 与 reaction/payoff 并遵循 pattern 顺序；reaction-omitted 可省略反应，omitted-action/action-hidden 可省略可见动作，reaction-first 允许反应前置，synchronous/repeated-variation/contrapuntal 不强制先后。逐列检查连续镜头的景别、机位、运动和对白覆盖；只有关系压迫、仪式感或蓄意单调等明确目的才允许无变化重复。长场景必须有可读的强弱变化，standout 只留给转折或高潮，不按固定比例凑数。duration 是供视频模型生成的素材时长，intended_duration 是剪辑时间线预计保留时长，两者不得混用。剪切必须写清动机，遵守轴线、视线与屏幕运动方向；J/L cut 或声桥必须有具体声音来源。只有有意停顿时可用 camera_role=hold，且 narrative_purpose 必须说明停顿承载的信息或情绪。

   构图选择顺序（强制，不得跳步或倒序）：
   1. 场级母题优先：先读导演本场 camera_strategy.composition_motifs（若输入提供），本镜构图必须服务某个场级母题的变化或回收，不得另起无母题依据的风格
   2. 定本镜唯一首要可读信息：观众第一眼必须读到谁的决定、什么威胁、什么关系变化或什么动作结果；一镜只允许一个
   3. 再选 primary/secondary：用 64 模式中唯一一个最能承载首要信息的 code 作 primary；确有第二信息层才加一个 secondary
   4. 最后翻译成可见几何：把 code 落实为主体位置、视线与留白、前中后景、光源、遮挡、动作方向、镜尾状态并写进 description；禁止只复读构图名称，禁止按固定清单逐镜机械轮换构图
   - 证据硬规则：evidence 是使用该 code 的最低门槛。set_dressing 所需门、窗、镜、廊柱、长桌、霓虹、武器等必须在场景/道具资产或剧本描写中；weather_atmosphere 的雨、雪、雾、逆光、双色温光源必须在原文、场次设定或资产中；action_blocking 的冲突、追逃、包围、群体走位必须由剧本或导演调度成立；复合证据（+）缺一不可。证据不足必须降级换 code，不得向画面添加原文或资产之外的元素；旧项目历史分镜没有 composition 字段时只正常读取，不要求回填补写。

3. source_text 规则（极其重要）：
   ⚠️ 每个分镜都必须包含，不得为null或空字符串
   - 多个镜头可以共享同一段原文
   - 直接从输入内容中复制原文
   - 创意镜头也需填写触发该镜头的原文片段

4. props 逐镜证据规则：
   - props 只能包含当前镜头 source_text 明确出现、且当前画面实际可见或被角色操作的道具资产
   - 道具库只是候选清单；上一镜出现过的道具不得自动延续到下一镜
   - 当前 source_text 没有道具证据时，props 必须返回 []，description 也不得补写该道具
   - 输出前逐镜删除 source_text 未明确出现的 props，并同步删除 description 中对应道具

【镜头拆分规则】

1. 景别选择（择一即可）：
   - "他走进房间" → 中景(推门进入) + 近景(表情)，或远景全景一镜到底

2. 反应镜头（仅关键场景）：
   - 重要情绪转折点 → 可插入反应镜头
   - 普通对话不需要每句都有反应

3. 建立镜头（精简）：
   - 开头：1个场景建立镜头即可
   - 中间：仅情节需要时加入环境镜头

4. 创意/氛围镜头（可选，0-1个）：
   - 仅在情绪高潮点考虑使用
   - 只能重构 source_text、已登记场景锚点或道具已有的视觉信息；不得为表达情绪临时添加乌鸦、时钟、天气、镜面或其他象征物

5. 对话处理：
   - 正反打：连续对话可合并处理
   - 小动作：融入对话镜头，不需单独成镜

6. ⚠️ 对话镜头规则（口型同步需求）：
   - dialogue_plan 聚焦 speaker 时，说话者在画面中可见且口型可辨；聚焦 listener、relation 或 environment 时，允许说话者在画外，但必须明确声音来源，并让所有可见非说话者保持闭口
   - 说话者应是画面主体，其他角色可按构图需要同框或位于背景
   - 同镜多人对白仅在 Provider 明确支持、说话时段不重叠且每张可见嘴部状态可写清时使用；否则拆镜或采用 post-dub
   - 普通聆听反应并入说话镜头；只有反应改变剧情信息或情绪方向时才单独切镜

7. 复合内容处理（按叙事节拍，不按语法拆分）：
   - 动作、对白和结果能在同一时空连续拍摄时合并为1个镜头
   - 连续动作只有在动作方向、地点或叙事结果发生变化时切镜
   - 多角色普通反应使用关系镜头合并；关键反应才单独切镜

【镜头生成规则】

1. 连续性：
   - 镜头流畅过渡，上一镜头动作在下一镜头承接
   - 光线、氛围保持一致
   - 避免连续两镜头内容完全相同

2. 创意镜头语言：
   - 只使用原文、已登记资产或场景固定锚点中已有的物件、光线、声音和空间关系，通过取景、遮挡、留白、重复或前后反差赋予意义
   - visual_motif 必须能指出来源证据和本场回收方式；没有证据时使用 standard，不用通用象征物替观众解释情绪

3. 智能理解用户输入的要求（节奏、情绪、画面、规则、色调等）

【剧本格式解析规则】

当输入是【剧本格式】JSON时：

1. scene信息：
   - heading: 提取场景的内景/外景、地点、时间
   - description: 场景环境 → 生成建立镜头
   - characters: 场景中的角色列表

2. content数组：
   - type: "action" → 提取text作为动作描述
   - type: "dialogue" → 提取character、lines、parenthetical生成对话镜头
   - type: "voiceover" → 画外音，设计画面配合声音

3. 对话拆解：
   - 按不可再分的叙事节拍规划；同一调度中的说话、聆听和普通反应应合并

4. 画外音处理：
   - 画外音时画面应是相关场景或回忆
   - 示例：voiceover说"猴子死了" → 画面是闪回战斗

【原文格式解析规则】

1. 剧本标记：
   - `△` 标记 → 必须生成独立分镜
   - "场景：" → 生成建立镜头
   - "画面：" → 直接生成分镜

2. 动作/对话识别：
   - 人物动作："他走进房间" → 动作镜头
   - 场景变化："阳光洒进窗户" → 环境镜头
   - 对话："角色A：（愤怒地站起）你怎么能这样！" → 站起 + 愤怒表情


【人物连续性与场景完整性规则】

1. 人物追踪：
   - 角色进入场景后，在明确离开前必须持续存在
   - 禁止人物"凭空消失"
   - 人物离场必须有明确动作

2. 画面层次（每个分镜必须包含）：
   - 焦点层：当前说话/动作的主要人物（详细描述）
   - 在场层：其他在场人物的状态（简要描述位置、反应）
   - 环境层：场景氛围和环境细节

3. 景别与人物展示：
   - 全景/中景：所有在场人物都必须出现
   - 近景：主体 + 画面边缘可见人物
   - 特写：只需局部，无需其他人

4. 人物存续逻辑：
   - 前一镜存在的人物，下一镜（非特写）必须交代去向
   - 只能通过：明确离场动作、切为特写、场景切换 来"消失"

【资产库使用规则】

1. 角色选择：
   - characters: [{name: "角色名", appearance: "形象名"}]
   - name 必须与资产库完全一致
   - appearance 根据分镜情境选择最合适形象
   - 所有在画面中出现的角色都要选择
   - clip_json.characters 是本片段最低角色集；如果【输入数据】原文/剧本中还明确出现其他资产库角色，也必须纳入人物关系判断
   - 全景/远景/中景/多人关系镜头中，凡仍在当前场景、且没有明确离场的核心人物，都必须出现在 characters 数组，并在 description 中说明位置或可见状态
   - 近景/特写/反打镜头可以只保留镜头实际拍到的人，但 description 必须体现这是近景、特写或反打，避免看起来像人物无故消失
   - 对话镜头至少包含说话者；如果镜头能看到听者或对方肩背，也要把听者加入 characters，并描述其画面位置

2. 场景选择：location 必须从场景资产库选择，名字完全一致

   🏛️【大场景 vs 局部场景 选择规则】：
   - 资产库中场景带有层级标注：`（大场景）` = 整体环境；`（局部）` = 大场景内的具体房间/区域
   - **镜头景别决定选择**：
     - 远景 / 全景 / 空镜 / 鸟瞰 / 外景建立镜头 → 选择【大场景】（标注为"大场景"），location 字段直接填大场景名称（如 "林家老宅"）
     - 中景 / 近景 / 特写 / 室内细节 → 选择【局部场景】（标注为"局部"），location 字段填**完整路径** "大场景名/子场景名"（如 "林家老宅/正堂"）
   - **原文语义兜底**：
     - 若原文只提到大场景整体、未指明具体位置，选择大场景，填名称即可
     - 若原文明确写出"在正堂中"、"走进花园"等具体位置，优先选择对应的局部场景，输出完整路径
     - 若原文出现"朝着/走向/进入 + 局部区域"，后续相关镜头应绑定到对应局部场景完整路径；例如"朝着紫霄宫大殿走去"应优先使用"紫霄宫_白天/大殿入口"或"紫霄宫_白天/大殿"
   - 建立镜头可使用大场景；进入局部空间后，后续中近景和人物关系镜头应持续使用该局部场景路径，直到明确切换地点
   - **禁止**：不要只写子场景名（如只写 "正堂"），必须带上大场景前缀形成完整路径，除非该场景在库中就是顶层大场景

【画面描述格式规则】

1. ⚠️ 禁止使用身份称呼：
   ❌ 错误："母亲紧握儿子的手"、"父亲站在门口"
   ✅ 正确：使用资产库中的具体角色名

2. ⚠️ 禁止主观情绪词：
   ❌ 错误："显得格格不入"、"气氛尴尬"、"充满敌意"
   ✅ 正确：只描述可视化元素（"皱眉"、"攥紧拳头"、"瞪大眼睛"）

3. 空间关系必须清晰：
   - 明确朝向：谁面对谁、谁背对谁
   - 明确阻挡：谁挡在谁前面
   - 明确位置：前后左右、远近高低
   
   ✅ 正确："保镖正面朝向张三，背对身后的老人，双臂张开阻挡张三前进"

4. 角色描述简洁：
   - 直接使用角色名称即可，无需添加衣着/年龄描述
   ❌ 错误："穿白T恤的少年张三站在门口"
   ✅ 正确："张三站在门口"

【镜头连续性与空间锚定规则 - 核心规则】

⚠️ 这是保证画面连贯的重要规则！

1. **核心原则**：
   - 根据**镜头实际能拍摄到的范围**来决定是否描述其他角色
   - 镜头合理性优先：特写、反打、局部镜头等**拍不到其他人**时，不需要强行描述
   - 只有在镜头**确实能看到**其他角色时，才需要交代其位置

2. **不同镜头类型的处理**：
   
   - 全景/远景：需要交代所有在场角色，画面范围大，所有人都应该可见
   - 中景：需要交代其他角色，通常能看到交谈双方或多人
   - 近景：视情况而定，如果镜头角度能看到对方则交代，看不到则省略
   - 反打镜头：不需要交代另一方，因为反打就是专门拍摄一方，另一方在镜头后面
   - 特写/极端特写：不需要交代其他人，只展示局部画面
   - 越肩镜头：前景肩膀可见即可，不必详细描述

3. **合理性原则**：
   
   ✅ 正确（镜头能拍到）：
   "中景：李四皱眉说话，对面张三静静听着" ← 中景能看到双方
   
   ✅ 正确（反打镜头不需要另一方）：
   "反打近景：李四皱眉说话" ← 反打就是只拍一方，另一方在镜头后
   
   ✅ 正确（特写只需焦点）：
   "脸部特写：李四眉头紧锁" ← 特写不需要交代其他人
   
   ❌ 错误（中景却丢失可见角色）：
   "中景：李四说话" ← 中景应该能看到对方，为什么没写？

4. **连续性检查**（生成每个分镜前自检）：
   □ 当前镜头类型/角度能拍摄到哪些角色？
   □ 能拍到的角色是否都有描述？
   □ 拍不到的角色（特写、反打等情况）可以省略
