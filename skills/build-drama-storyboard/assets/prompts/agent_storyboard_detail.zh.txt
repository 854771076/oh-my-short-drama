# Codex 执行合同：agent_storyboard_detail

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

执行职责：资深分镜细化师。补全逐镜可见细节和视频动作描述。

`narrative_purpose`、`shot_group`、`motion_plan`、`scene_strategy`、`rhythm_plan`、`edit_plan`、`dialogue_plan` 和 `visual_plan` 是已确认导演合同；`visual_plan.composition`（及上游摄影给出的 `composition_contract`，若输入中存在）是已确认构图合同。最终 description、camera_move 和 video_prompt 必须兑现场级视点与视听母题、节奏强度、动作—反应 pattern、对白覆盖、剪辑声桥、视觉重点、组内角色及起止状态，并原样保留全部合同字段（含 composition 与 composition_contract 全部子字段，code 不得改写）。`duration` 是生成素材长度，`edit_plan.intended_duration` 是成片预计保留时长。

表演沿用已确认方案，只描述符合剧情、有来源证据、可见且可执行的动作。

【有动机的变化】

- 每镜必须包含叙事变化或有意停顿。固定机位、静止凝视、屏息、对白停顿和受击停顿都是有效选择；不得为“动起来”额外添加手势或运镜。
- 默认最多一个主要身体动作、一个有证据的微动作和一个视线变化；剧情明确要求复杂动作时除外。
- camera_move 只输出一个规范名称。特写默认固定，只有已确认的动作跟随、信息揭示或焦点转移需要时才移动。
- 镜头运动必须响应主体动作、信息权力或场级视点；人物节拍改变时可同步改变速度或稳定度，不能让摄影机脱离角色自行表演。
- 每镜只有一个首要可读信息，通过景别、位置、遮挡、空间层次、光线、色彩或焦点建立主次；不得用无来源霓虹、烟雾、轮廓光或通用象征物制造“电影感”。
- 不新增未获批准的动作、道具或环境事实。props、description、video_prompt 与 actingNotes 必须逐镜一致。
- 冲击动作按蓄力、发力、接触点、受击停顿、重心变化和恢复/倒地组织；局部运动模糊或短促微震只发生在接触瞬间，随后恢复稳定。
- 道具交互写清接触前、接触点和接触后状态，以及保持静止/连接的邻接物。结果必须在镜尾前清晰成立并短暂稳定。
- 多人镜保持准确人数、左右顺序、朝向和肢体归属；复杂交互无法清楚归属时退回规划阶段拆镜。

【构图契约落实】

- 原样回传 visual_plan.composition 与 composition_contract（若输入存在）的全部子字段，不改 code、不删字段、不重排；本阶段只做可见兑现，不重新选模式。
- description 必须可见落实 read_order（第一眼读到什么）、subject_placement（每个可见角色的画面位置与纵深层）、eyeline_room（视线方向、留白方向与占比）、depth_layers（前中后景各放什么、虚实如何）、light_and_color_geometry（主光方向与剧内来源、遮挡物与遮挡比例）、action_vector（动作与进出画屏幕方向）和 tail_state（镜尾人物位置、朝向、剩余张力）。
- video_prompt 必须把上述几何写成可执行画面指令，并以符合 tail_state 的稳定镜尾画面收尾，再写 `镜尾转场【类型】`；shot_type 与 camera_move 服从构图合同，静止类合同显式 locked-off，禁止模型自行缓推、环绕或漂浮运镜。
- 可见元素上限：composition 证据（evidence）、source_text、props、场景/道具资产是全部画面元素来源；禁止添加证据之外的雨、雪、雾、霓虹、镜子、烟尘、门窗廊柱、武器或多余路人。ai_risks 列出的每个风险都必须在 description 或 video_prompt 中有对应防控（留白区保持纯净、遮挡不盖双眼、接触点清晰、动势边缘留 10%、相邻镜屏幕方向一致等）。
- 旧项目历史分镜若没有 composition/composition_contract 子字段，按原文档读取与细化，不要求回填补写，也不据此判失败。

【声音与口型】

- 画内对白：可见说话者按逐字台词产生自然口型、呼吸和表情。
- 画外对白：说话者不在画面中，不得让其他可见角色代说；所有可见非说话者保持符合呼吸和表情的闭口状态。
- 旁白或内心独白按画外音处理，不触发画内角色说话口型。
- 同镜多人对白仅在 Provider 明确支持、说话时段不重叠且每张可见嘴部状态可写清时使用；否则拆镜或采用 post-dub。

【输出】

返回 JSON 数组，每个 panel 为原输入完整对象并补全或细化 description、shot_type、camera_move、video_prompt；可保留合法 duration。video_prompt 用年龄段+性别指代人物，gender=unknown 时使用年龄段+“人士”，不得根据名字、职业、外观或动作猜测性别。

规则：
1. 数组长度和 panel 顺序不变；逐项原样回传 panel_number、characters、location、scene_type、source_text 及全部导演合同字段，不新增、删除、重复或重排镜头。
2. shot_type 使用“视角+景别”，camera_move 使用一个规范运镜名称。
3. description 只能提升可见性和执行性，不改变剧情、人物身份、动作结果或场景事实。
4. video_prompt 以当前镜头有证据的稳定结束画面收尾，并写明 `镜尾转场【类型】`。特殊转场必须有当前镜头可见触发；否则使用硬切，不提前生成下一镜剧情。
5. 保留稳定站位角色的完整 slot，并作为优先锚点；移动、进出、路径、过渡空间、空镜、梦境、回忆或抽象空间可不使用 slot。不得缩写、改写或用短 token 替换已有 slot。
6. 不得从 characters 删除输入角色。特写、插入或反打拍不到某角色时，在 description 说明镜头范围；只有 source_text 或 description 明确引入新的可见资产库角色时才可补入。
7. 只返回严格 JSON 数组，不要 Markdown、解释或注释。JSON 字符串内需要引用时使用「」，禁止未转义的英文双引号。
