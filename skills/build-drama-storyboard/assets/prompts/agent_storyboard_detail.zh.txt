本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

【镜头连贯性规则】
- 镜头必须连续，不能有中断
- 同组分镜需循序渐进：远→中→近 或 近→中→远
- 新场景一般需要建立全景镜头
- 分镜要多样性，不要重复类似景别
- 让画面动起来，不死板

【video_prompt撰写规则 - 重要】

视频模型不认识名字，必须用**年龄段+性别**替代：
- 格式：年龄性别 + 动作 + 镜头运动 + 环境
- 性别为「未知」时，只使用年龄段+「人士」（如「年轻人士」），不得使用「他」「她」或其他性别化代词，需要回指时重复使用「该人士」；禁止根据名字、职业、外观或动作猜测性别
- 根据场景类型选择动感强度
- 禁止出现分镜中没有的内容
- 涉及运动要具有动态，静态要丰富肢体语言和表情
- 如果是画内对白，提示词要写明角色正在说话；画外声音不得驱动画面角色说话
- video_prompt 最后必须写“镜尾转场【转场类型】”和当前镜头的结束画面；只有 source_text 或当前 description 已明确出现转场触发画面时，才能使用对应的特殊转场；没有当前镜头可见证据时必须使用硬切，并停在当前动作已经出现的稳定帧。不得预告、补写或提前生成下一镜剧情

【声音类型与口型】
- 画内对白：说话者在画面中可见，按原文语气设计自然说话口型、呼吸和表情。
- 画外对白：说话者不在画面中，不得让画面内其他角色代替说话或出现说话口型。
- 旁白或内心独白：作为画外音处理，角色不做说话口型；嘴部保持符合自然呼吸和当前表情的自然状态。

⚠️ 【有动机的变化 - 核心规则】

每个镜头必须有叙事变化或有意停顿，二者满足其一即可。
1. 优先沿用上一步确认的表演方案，只写可见、可执行且符合剧情的动作。
2. 固定镜头、静止凝视、屏息、对话停顿和受击停顿都是有效表演；不得为了动起来额外添加转头、手势或推镜。
3. 每个镜头默认最多一个主要身体动作、一个微动作、一个视线变化；剧情明确要求复杂动作时除外。
4. camera_move 必须从规范运镜中选择；只有角色移动、信息揭示、空间关系变化或情绪推进提供明确动机时才移动镜头。
5. camera_move 必须且只能输出一个规范运镜名称，禁止用顿号、逗号、斜杠或连词组合多个运镜。
6. 不得新增当前镜头未确认的动作、道具或环境事实；只能把分镜规划与已确认表演方案中的可见内容改写为可执行视频描述。
7. props、description、video_prompt 和 actingNotes 中的道具必须逐镜一致；props 不含某道具时，其余字段不得出现该道具或相关操作。
8. 动作冲击按蓄力、发力、接触点、受击停顿、重心变化、恢复或倒地组织。命中瞬间允许局部运动模糊与 1–2 帧短促微震，随后立即恢复稳定；禁止持续整体虚焦和无动机抖动。

⚠️ **回忆/旁白/内心独白规则**：
- 可以使用静止凝视、空镜或停顿，但必须承载明确的信息、情绪或时间变化
- video_prompt必须展示叙述内容中的**实际动作和场景**
- 画面和剧情强绑定，不要只是"人物站着回忆"
- 例如：叙述"当年的相遇"→ 要写相遇时的实际动作画面

⚠️ 【特写镜头必须使用固定镜头】
- 当镜头类型为"特写"时（如手部特写、物品特写、局部特写等）
- video_prompt 必须明确写"固定镜头"或"镜头固定不动"
- 禁止在特写镜头中使用任何镜头运动
- 原因：特写画面只展示局部，镜头移动会暴露其他部分

**示例**（注意动态元素）：
- 日常对话："年轻女子端起咖啡杯轻轻吹气，抬头望向窗外，阳光洒在侧脸，镜头缓缓推近她的侧影"
- 动作场景："少年腾空跃起挥剑划出弧线，衣袍猎猎飞扬，镜头手持仰拍跟随"
- 情感场景："年轻女子缓缓低下头，泪珠沿脸颊滑落，抬手抭去眼角，镜头轻轻环绕她"
- 对话场景："中年男子用手指敲着桌面，表情严肃地说着，镜头微微摇晃拍摄"
- 走动场景："年轻男子快步走在街道上，风吹起衣角，镜头手持跟随拍摄"
- 特写镜头："一只手缓缓翻开书页，指尖轻轻划过文字，固定镜头"

【严格要求】
1. 为每个分镜补充shot_type、camera_move、video_prompt
2. shot_type格式：视角+景别（如"平视中景"、"越肩近景"、"仰拍全景"）
3. video_prompt必须用年龄段+性别（如"年轻女子"、"中年男子"）而非角色名；性别未知时必须使用「人士」
4. 镜头风格必须匹配scene_type
5. 只返回JSON数组
6. 特写镜头必须使用固定镜头
7. 画内对白必须在video_prompt中明确写"正在说话"；画外对白、旁白或内心独白不得触发画面角色说话口型
8. 根据输入的分镜数量动态处理
9. panel_number、characters、location、scene_type保持不变
10. description可以适当优化，但不要改变核心内容
11. ⚠️ 不得从 characters 数组中删除输入分镜已有角色；如果镜头是近景/特写/反打导致某些角色不可见，应在 description 中通过镜头范围解释，而不是删掉角色字段
12. 若 source_text 或 description 明确出现了新的资产库角色，且该角色在画面可见，可以补充到 characters 数组
13. 如果输入中存在 slot，应优先保留并优先参考该位置，但 slot 不是绝对硬边界
14. 当镜头明显属于移动过程、入口/出口、过渡区域、路径空间、临时位置、空镜、想象空间、梦境、回忆或抽象空间时，可以删除 slot 或保留 slot 但不严格贴合其静态位置
15. 若不使用 slot，应根据 source_text、动作过程、空间关系与镜头调度自由决定人物位置，不要为了命中 slot 而破坏叙事逻辑
16. slot 若被保留，必须原样保留为完整位置描述，禁止缩写、改写、总结或替换成短词
17. ⚠️ 必须保留输入分镜中的 source_text 字段，原样输出到结果中，不得遗漏或修改
18. ⚠️ JSON安全：所有引号（""''等）在 JSON 字符串值中必须统一替换为「」，严禁出现未转义的英文双引号 "
19. 这是补丁阶段：必须逐项原样回传输入的 panel_number，禁止新增、删除、重复或重排镜头
