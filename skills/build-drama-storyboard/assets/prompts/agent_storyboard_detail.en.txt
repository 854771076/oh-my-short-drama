For performance, preserve the acting plan already confirmed in the previous step and describe only visible, executable actions that fit the story.

[MOTIVATED CHANGE]
Each shot must contain either a narrative change or an intentional pause. Static framing, held gaze, breath holds, dialogue pauses, and impact pauses are valid performance choices; never add gestures or camera moves merely to keep things moving. By default use at most one primary body action, one micro-action, and one eyeline change unless the story explicitly requires a complex action. For impact, describe anticipation, force, contact point, impact pause, weight shift, and recovery or fall. At contact, localized directional motion blur and a brief contact-synchronized micro-shake are allowed, followed by immediate stability; forbid sustained global defocus and unmotivated shake.

camera_move must contain exactly one canonical movement name. Do not join multiple movements with commas, slashes, or conjunctions.
Close-ups default to locked framing and move only for an approved action follow, information reveal, or focus transfer. Camera behavior follows subject action, information power, or scene viewpoint; it may change speed or stability with an evidenced beat, but never performs independently of the character.
Give each shot one primary readable fact and build hierarchy through scale, placement, occlusion, depth layers, light, color, or focus. Never add arbitrary neon, smoke, rim light, or generic symbols merely to look cinematic.
Do not add actions, props, or environmental facts not approved for the current shot. Only turn visible content from the storyboard plan and approved acting plan into executable video wording.
Props mentioned in props, description, video_prompt, and actingNotes must agree shot by shot. If props omits an asset, no other field may mention that asset or an action involving it.
For prop contact, state the before/contact/after states and any adjacent object that stays attached or still; make the result clearly true and briefly stable before the exit frame. In group shots preserve exact headcount, left-to-right order, facing, and limb ownership; send interaction that cannot stay attributable back for shot splitting.

[COMPOSITION CONTRACT REALIZATION]
- Echo every subfield of visual_plan.composition and composition_contract (when present) unchanged: do not reselect codes, delete fields, or reorder; this stage only realizes the geometry.
- description must visibly realize read_order (what is read first), subject_placement (each visible character's screen position and depth layer), eyeline_room (gaze direction, negative-space direction and share), depth_layers (what sits in foreground/midground/background and how sharpness falls), light_and_color_geometry (key direction and its in-story source, occluders and occlusion ratio), action_vector (screen direction of action and entrances/exits), and tail_state (end-frame position, facing, residual tension).
- video_prompt must turn that geometry into executable screen instructions and end on a stable tail frame consistent with tail_state, followed by `Transition out [transition type]`. shot_type and camera_move obey the composition contract; static-pattern contracts explicitly say locked-off; forbid autonomous slow pushes, orbits, or floating camera moves.
- Visible-element ceiling: composition evidence, source_text, props, and scene/prop assets are the only sources for picture elements. Never add rain, snow, fog, neon, mirrors, smoke, doors/windows/columns, weapons, or extra bystanders without evidence. Every risk in ai_risks needs a visible countermeasure in description or video_prompt (clean empty zones, occlusion never covering the eyes, clear contact point, 10% margin at motion edges, screen direction continuous with neighbors).
- Legacy panels that lack composition/composition_contract subfields are read and refined as-is: no backfilling and no failure verdict on those grounds.

[VOICE TYPE AND LIP MOVEMENT]
- On-screen dialogue: the visible speaker may use natural speaking lip movement, breath, and expression matching the verbatim line.
- Off-screen dialogue: the speaker is outside the frame; never make another visible character speak the line or use speaking lip movement.
- A voice-over or inner monologue is off-screen audio: the visible character has no speaking lip movement, keeping a natural mouth position consistent with breathing and the current expression.
- Use multiple speaking faces in one shot only when the Provider supports it, speech windows do not overlap, and every visible mouth state can be scheduled; otherwise split coverage or use post-dub.

Rules:
1. Keep panel order unchanged.
2. Keep source_text semantically aligned with input; do not rewrite story meaning.
3. video_prompt should be motion-ready and concrete. End it with `Transition out [transition type]` and the current shot's motivated exit frame. Use a special transition only when its visible trigger already appears in source_text or the current description; otherwise, you must use a hard cut when the current shot has no visible evidence for a special transition, ending on a stable frame of an action already shown. Never foreshadow, add, or generate the next shot's story action.
4. Use age+gender wording in video_prompt when naming actors in camera directions. When gender is "unknown", use the age band plus "person" (for example, "young person"). Do not use gendered pronouns; repeat "the person" when a reference is needed. Never infer gender from a name, occupation, appearance, or action.
5. Preserve every input `slot` when the character is stably positioned, and reflect it as a preferred anchor in refined description/video_prompt.
6. Do not remove characters that already exist in the input panel's `characters` array. If a close-up, insert, or reverse shot makes some characters invisible, explain the tight framing in `description` instead of deleting the character field entry.
7. If source_text or description clearly introduces another asset-library character who is visible in the shot, you may add that character to `characters`.
8. `slot` is not an absolute boundary. If the shot is clearly about movement, entry/exit, path traversal, transition space, temporary space, empty space, imagination, dream, memory, or abstract/non-literal space, you may remove `slot` or keep it without forcing a rigid static match.
9. When no `slot` is used, decide placement freely from source text, action flow, spatial logic, and cinematic staging.
10. Do not shorten, rewrite, summarize, or replace a provided `slot` phrase with a short token.
11. Return JSON array only.
12. ⚠️ JSON SAFETY: All quotation marks in text (""''「」 etc.) MUST be converted to corner brackets「」in JSON string values. NEVER use raw ASCII double quotes " inside string values.
13. This is a patch phase: echo every input panel_number in the same order; never add, remove, duplicate, or reorder panels.
