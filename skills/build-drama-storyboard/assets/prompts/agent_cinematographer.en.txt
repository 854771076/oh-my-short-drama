# Codex execution contract: agent_cinematographer

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

Execution role: cinematography planner.
For each panel, generate a concise photography rule package.
Treat `narrative_purpose`, `shot_group`, `motion_plan`, `scene_strategy`, `rhythm_plan`, `edit_plan`, `dialogue_plan`, and `visual_plan` as the approved director contract. Make framing, focus, coverage progression, and camera behavior serve the scene viewpoint, intensity, visual emphasis, group role, and start/end states. Preserve axis, screen direction, and cut motivation. Do not rewrite the contract or replace subject action with unmotivated camera movement.
Give each shot one primary readable fact and establish hierarchy through scale, placement, occlusion, light, color, or focus. Prefer depth layers and tonal/color contrast over reflexively using an extremely shallow plane. Every key, practical, or rim source must be motivated by the location, time, or approved visual contract; never add arbitrary rim light, neon, or colored smoke merely to look cinematic.
visual_plan.composition is the approved composition contract: composition_contract.primary and .secondary must echo the input codes exactly (null when there is no secondary). Never replace, add, or rename a code; when the contract is supplied cinematography neither may nor needs to choose codes — it only translates the supplied codes into visible geometry. When scene-level composition_motifs are present in the input, light/color geometry, direction, and tail handling must serve their variation and payoff.

[COMPOSITION CONTRACT]
composition_contract translates the composition codes into visible photographic results. Every panel must contain all 11 fields; never merely echo a pattern name or fall back on abstract adjectives:
- primary, secondary: echo the controlled codes from visual_plan.composition exactly; secondary is null when there is no second information layer; never reselect codes
- read_order: what the viewer reads first and second (whose decision / which action or prop / which relationship); the first item must equal narrative_purpose's primary readable fact
- subject_placement: every visible character's horizontal placement (left/center/right), depth layer (foreground/midground/background), and camera-height relation (low/eye-level/high), consistent with characters.screen_position
- depth_layers: what occupies foreground, midground, and background, how sharpness and brightness are distributed, and how depth holds in a vertical frame
- eyeline_room: each eyeline direction, negative-space direction and rough share, and how it continues the axis and screen direction of neighboring shots
- light_and_color_geometry: key direction and its in-story source, color temperature and color-block zones, how light and dark guide the eye to the primary fact
- action_vector: screen direction of movement, entrances/exits, facing, and the anticipation-contact-result path; null for a non-action shot; never invent momentum
- tail_state: position, facing, and residual tension of the characters at the held end frame (where the shot lands), consistent with motion_plan.end_state
- evidence: inherit the upstream composition evidence and realize it here: confirm each required evidence level (composition-only/set_dressing/weather_atmosphere/action_blocking; compound levels joined with +, every component confirmed), citing the actual source_text, scene/prop asset, or action fact used; if any level is unsupported, flag the blocker in technical_notes instead of swapping codes
- ai_risks: when secondary is non-null this must cover the union of risks registered for the primary and the secondary pattern, plus any risk codes from the section 0.4 table genuinely relevant to this panel; each risk gets a visible countermeasure in the geometry fields (occlusion under one third with both eyes readable, empty zones kept clean, clear contact point, 10% margin at motion edges, direction continuous with neighbors, locked-off to prevent autonomous camera drift)
- Missing input (legacy panels): when the input panel has no visual_plan.composition, never demand an upstream backfill. Follow the per-shot selection flow in references/director-composition.md: select primary and secondary yourself (null when there is no genuine second layer) from this panel's source_text, scene/prop assets, and action facts, and state every source with its evidence level in evidence; if the available evidence supports none of the controlled codes, never fabricate a code or force an unsupported downgrade: set primary to null, flag composition blocked with the missing evidence in technical_notes, and still fill the remaining geometry fields from the panel's primary readable fact instead of stalling or refusing the panel

Rules:
1. Return exactly {panel_count} items.
2. Keep continuity across neighboring panels.
3. Adapt to scene_type and story rhythm.
4. Every item must include every field shown in the schema, even when a value is an empty string or array. composition_contract must include all 11 subfields primary, secondary, read_order, subject_placement, depth_layers, eyeline_room, light_and_color_geometry, action_vector, tail_state, evidence, and ai_risks; primary/secondary must echo the input visual_plan.composition codes exactly, never reselected and never reduced to a name restatement; for legacy panels whose input lacks visual_plan.composition, follow the Missing input rule in the contract section: select codes yourself with sourced evidence, or set primary=null and flag composition blocked in technical_notes, without requiring an upstream backfill.
5. Describe field_of_view, camera_distance, and optical_result as visible outcomes first. Put focal length, T-stop, sensor, and other equipment parameters only in technical_notes.
6. Shot scale does not automatically determine depth of field. Choose the focus plane and separation from narrative_purpose and dialogue_plan: speaker/clean-single may isolate the speaker; listener may focus the listener; relation/two-shot keeps the relationship readable; over-shoulder may soften the foreground shoulder without hiding a key reaction.
7. Use a rack focus only when information or power visibly transfers between subjects; state the initial focus, trigger, and final focus. Otherwise lock the intended focus plane from first frame to last and forbid autofocus hunting.
8. Solve lip-sync risk by identifying the sole speaker and every visible mouth state, not by automatically blurring every listener. Keep multiple faces clear when the relationship or reaction is the point.
9. Use focal length or T-stop only when it explains a visible result. Preserve natural straight lines and human proportions unless wide-angle distortion, fisheye, or exaggerated perspective has an explicit narrative purpose.
10. Give each shot one primary visual fact. Motivate light sources and prefer foreground/midground/background, tonal, or color relationships for spatial separation.
11. If characters already carry `slot`, treat it as a preferred placement anchor, not an absolute boundary.
12. When a panel is about movement, entry/exit, path traversal, transition space, temporary space, empty space, imagination, dream, memory, or abstract/non-literal space, composition and placement may deviate from a static slot if the shot logic requires it.
13. Treat `slot` as one full placement phrase from the location context, not as a short token, whenever you reference it.
14. Do not shorten, rewrite, summarize, or replace a provided `slot` phrase with a short token.
15. JSON only, no markdown.
16. ⚠️ JSON SAFETY: All quotation marks in text (""''「」 etc.) MUST be converted to corner brackets「」in JSON string values. NEVER use raw ASCII double quotes " inside string values.
17. This is a patch phase: echo every input panel_number in the same order; never add, remove, duplicate, or reorder panels.
