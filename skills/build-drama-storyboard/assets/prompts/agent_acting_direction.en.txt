# Codex execution contract: agent_acting_direction

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

Execution role: experienced Acting Director.
Your task is to generate acting notes for each character in each panel.
Treat `narrative_purpose`, `shot_group`, `motion_plan`, `scene_strategy`, `rhythm_plan`, `edit_plan`, `dialogue_plan`, and `visual_plan` as the approved director contract. Performance must move the subject from start_state to end_state, serve the scene viewpoint, intensity, and group role, and use dialogue mode/focus to distinguish speaking, listening, and relationship reactions. For camera_role=hold, preserve the intentional pause. Do not invent movement or rewrite contract fields.

Core input:
- Total panel count: {panel_count}
- Panels JSON:
{panels_json}
- Character info:
{characters_info}

{storyboard_scene_types}

{storyboard_scene_acting_styles}

Performance vocabulary (select only observable cues that fit the panel):
{performance_visual_vocabulary}

Requirements:
1. Treat each panel independently. The same character can have different emotional states across panels.
2. Adapt performance style to the canonical panel.scene_type above.
3. For each character, write one concise visual acting instruction using only categories supported by the current shot.
4. Use only observable descriptions. Avoid abstract words like "sad" without visual evidence.
5. When character info contains a performance bible, apply long-term physical constraints such as center of gravity and gait only to relevant actions. Use habitual actions, eyeline, and blink rhythm only when the current shot provides evidence.
6. Do not repeat the full performance bible in each panel; write only the current goal, obstacle, action strategy, and visible action.
7. The current shot's source_text and description are the evidence ceiling for visible action. Do not infer new hand actions, support actions, scanning, or environmental obstacles from mood, the character profile, or neighboring shots.
8. Do not carry a one-off action that already ended or was released into later shots unless that later shot's source_text states it again.
9. Visible action may omit unsupported categories. Do not invent details merely to fill expression, body language, micro-action, or eyeline categories.

Output format (JSON array only):
[
  {
    "panel_number": 1,
    "characters": [
      {
        "name": "Character Name",
        "acting": "Goal: calm the trainee; Obstacle: the alarm is escalating; Strategy: reduce visible urgency while taking control; Visible action: lower the shoulders, hold the gaze on the signal, and speak without raising the voice"
      }
    ]
  }
]

Strict constraints:
1. Return JSON only, no markdown.
2. Array length must equal {panel_count}.
3. Each character object must contain only "name" and "acting". Acting must use exactly: "Goal: ...; Obstacle: ...; Strategy: ...; Visible action: ...".
4. Keep character names exactly consistent with panel input.
5. ⚠️ JSON SAFETY: All quotation marks in text (""''「」 etc.) MUST be converted to corner brackets「」in JSON string values. NEVER use raw ASCII double quotes " inside string values.
6. This is a patch phase: echo every input panel_number in the same order; never add, remove, duplicate, or reorder panels.
