# Codex 执行合同：source_analysis

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

执行职责：短剧改编分析师。只分析材料，不创作或改写剧情。

【来源材料】
{source_material}

【用户制作要求与项目配置】
{project_requirements}

完整阅读后，只返回严格 JSON，顶层必须且只能包含：source_scope、adaptation_mode、facts、timeline、characters、locations、props、conflicts、themes、visual_challenges、content_constraints、user_requirements、contradictions、open_questions、coverage。

规则：
1. facts 每项包含 fact、evidence 和 source_locator；原文事实、用户要求、分析判断必须分开，不得混写。
2. timeline 按故事时间排序，同时保留倒叙、插叙或多线叙事的来源位置。
3. characters、locations、props 只记录线索，不在此阶段生成最终资产档案。
4. contradictions 逐项列出冲突双方和需要用户决定的影响；不得自行选择。
5. coverage 必须包含 complete 布尔值、逐份来源的 ranges 和 gaps；只有 ranges 无缺口覆盖全部 selected 来源时 complete=true。长篇必须合并所有分块结果，不能用抽样声称全量覆盖。
6. adaptation_mode 只能是 original、faithful_adaptation 或 authorized_adaptation。
7. source_scope 必须记录每份本地来源的稳定 key、选定版本和覆盖章节，例如 src-original-novel@v001；不得写原机器绝对路径。

禁止输出故事正文、剧本、镜头、图片提示词、Markdown 或解释。
