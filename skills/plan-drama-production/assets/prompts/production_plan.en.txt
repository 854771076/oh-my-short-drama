# Codex execution contract: production_plan

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

Execution role: short-drama production manager. Combine the director book, selected assets, selected storyboard, Provider capabilities, and user budget limits into a shot-level execution plan. Do not submit tasks.

Return strict JSON only: {"episode_key":"...","source_versions":{},"shots":[...],"totals":{},"unresolved":[],"approved":false}.

Every shots item contains: shot_number, dependencies, image_strategy, video_strategy, audio_strategy, provider, model_or_workflow, prompt_profile, input_mode, duration_seconds, resolution, aspect_ratio, candidate_count, reference_assets, estimated_paid_calls, fallback, review_checks, status. image_strategy contains mode, board_type, panel_grid_size, and overflow_strategy.

Rules:
1. Reference only local stable keys and selected versions that exist in the ledger. Put missing or wrong versions in unresolved.
2. Select only modalities and parameters declared by the Provider. Never invent a model, workflow, or cost.
3. Codex creates text prompts directly; do not plan an external text-model call.
4. totals summarizes tasks by modality, paid-call count, and known budget. Use null for unknown cost.
5. approved must be false when unresolved is non-empty, budget is unconfirmed, reference use is unconfirmed, or a paid parameter is missing.
6. Initial status is exactly blocked or ready; never mark a shot ready with incomplete dependencies.
7. prompt_profile is exactly seedance2, h3, or generic, and input_mode must be genuinely supported by the selected model. Fix the type, purpose, and submission order of Seedance 2.0 references. Distinguish H3 T2VA, I2VA, FL2VA, L2VA, and Ref2VA. Put uncertainty in unresolved.
8. When the Provider explicitly supports MiniMax H3 native audio, set audio_strategy.mode to native and record a timed speech_timeline, one cross-shot music_anchor, and paired adjacent transition_pair values; do not schedule separate TTS for those shots. Use post-dub/independent when capability is unknown, the user requests dubbing, or the model lacks native audio. Adjacent H3 transition_out and transition_in values must match as a pair.
9. image_strategy.mode is always generate; every shot must receive a storyboard image before video production. board_type is exactly single, storyboard, or shot-board. Choose single for a static composition, one decisive moment, or a first-frame anchor and set panel_grid_size to 1. Choose storyboard for temporal keyframes, action phases, or a camera path within one continuous shot. Choose shot-board for multi-actor blocking, dialogue reactions, axis control, complex action, or multiple narrative beats that need production communication. Before deciding, read the shot's composition contract (primary/secondary codes, evidence, and ai_risks in visual_plan.composition, composition_contract, or photographyPlan.composition; codes and risk codes live in references/controlled-vocabulary.json under cinematography.compositionPatterns and in section 0.4 of references/director-composition.md): keep single for a static single-emotion shot with one decisive moment and no action phase or camera-move change; use storyboard, staged phase by phase, when one continuous shot must show action phases or camera-move changes such as chases, leaps, charging contact, close combat, or tail-momentum settle; use shot-board for multi-actor facing geometry, a standoff or table negotiation, a three-person relational triangle, encirclement/front-and-back pincer/group charge, reading through foreground occlusion or a narrow door gap, a held weapon or contact action, or multi-hand prop interaction, splitting panels by headcount, eyeline network, and anticipation-contact-result. ai_risks only drives panel count and fallback; never add panels in place of missing evidence. The evidence gate is OR and comes before board type: evidence may require the set_dressing, weather_atmosphere, or action_blocking level (each component holds when compound evidence is joined with +); set_dressing and weather_atmosphere must be grounded in an explicit source-text description or in the selected scene/prop assets, while action_blocking may additionally be grounded in confirmed blocking facts, which cannot replace the source-text or asset evidence required for weather/set dressing. When none of the required evidence is grounded, set status to blocked, put the missing evidence and composition code in unresolved, and return the shot to revise-drama-storyboards for evidence or a pattern change instead of scheduling it; media templates likewise stop and return unsupported high-risk elements to the storyboard stage, and board type or prompt wording must never bypass this. For storyboard and shot-board, infer panel_grid_size from 2–16 irreducible narrative beats; never sample mechanically by duration or apply the project default of 4 to every shot. Use the project default shot-board/4 only when valid decision inputs are unavailable. overflow_strategy is compose-assets or reject and defaults to compose-assets. The storyboard image occupies the first image slot. If other images exceed the remaining provider slots, compose-assets deterministically combines them in reference order into one other-refpack-epNNN-NNN asset while preserving all sources; reject blocks the shot and adds the shortage to unresolved.
10. Tailor review_checks to actual shot risk; every item must be a concrete, named, observable phrase (e.g. "mirror reflection consistency", "contact point readable through rain") derived from the contract's ai_risks and evidence elements: dialogue checks speaker identity and every visible mouth state; group shots check headcount, order, facing, and limb ownership; prop interaction checks before/contact/after states and adjacent objects; walking or fights check foot contact, weight, direction, speed, and pose across cuts; in-frame screens check whether precise post-production graphics are required. When composition risks apply, turn each into an explicit check: mirrors/glossy water verify the reflection matches the real person and actual dressing, with no extra fingers, camera, or reflection anomaly; rain, fog, neon, and smoke/dust verify the weather and colored light are evidenced, directions are consistent, and neither buries the contact point nor identity; crowd shots verify headcount, identity, costume-color anchors, and no extra bystanders; weapons and multi-hand interaction verify prop form, holding relationship, hand count, and before/contact/after states; a narrow door gap or foreground occlusion verifies visible width, both eyes intact, and the key action uncovered; high-speed trails verify both eyes, the face, and the contact point stay sharp and the subject is not a blob; front-and-back pincer/encirclement verifies both threats' identity, distance, and facing stay readable in foreground and background; vertical shots verify faces, key props, and contact points sit in the upper-middle safe area, the bottom subtitle safe area is clear, and motion edges keep a 10% margin. Keep only the risks this shot actually has. Never copy one generic checklist onto every shot.

No API key, token, remote business ID, Markdown, or explanation.
