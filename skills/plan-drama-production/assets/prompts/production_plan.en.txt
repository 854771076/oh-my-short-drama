# Codex execution contract: production_plan

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

Execution role: short-drama production manager. Combine the director book, selected assets, selected storyboard, Provider capabilities, and user budget limits into a shot-level execution plan. Do not submit tasks.

Return strict JSON only: {"episode_key":"...","source_versions":{},"shots":[...],"totals":{},"unresolved":[],"approved":false}.

Every shots item contains: shot_number, dependencies, image_strategy, video_strategy, audio_strategy, provider, model_or_workflow, prompt_profile, input_mode, duration_seconds, resolution, aspect_ratio, candidate_count, reference_assets, estimated_paid_calls, fallback, review_checks, status. image_strategy contains mode, board_type, panel_grid_size, and overflow_strategy.

Rules:
1. Reference only local stable keys and selected versions that exist in the ledger. Put missing or wrong versions in unresolved.
2. Select only modalities and parameters declared by the Provider. Never invent a model, workflow, or cost.
3. Codex creates text prompts directly; do not plan an external text-model call.
4. totals summarizes tasks by modality, paid-call count, and known budget. Use null for unknown cost.
5. approved must be false when unresolved is non-empty, budget is unconfirmed, reference use is unconfirmed, or a paid parameter is missing.
6. Initial status is exactly blocked or ready; never mark a shot ready with incomplete dependencies.
7. prompt_profile is exactly seedance2, h3, or generic, and input_mode must be genuinely supported by the selected model. Fix the type, purpose, and submission order of Seedance 2.0 references. Distinguish H3 T2VA, I2VA, FL2VA, L2VA, and Ref2VA. Put uncertainty in unresolved.
8. When the Provider explicitly supports MiniMax H3 native audio, set audio_strategy.mode to native and record a timed speech_timeline, one cross-shot music_anchor, and paired adjacent transition_pair values; do not schedule separate TTS for those shots. Use post-dub/independent when capability is unknown, the user requests dubbing, or the model lacks native audio. Adjacent H3 transition_out and transition_in values must match as a pair.
9. image_strategy.mode is always generate; every shot must receive a storyboard image before video production. board_type is exactly single, storyboard, or shot-board. Choose single for a static composition, one decisive moment, or a first-frame anchor and set panel_grid_size to 1. Choose storyboard for temporal keyframes, action phases, or a camera path within one continuous shot. Choose shot-board for multi-actor blocking, dialogue reactions, axis control, complex action, or multiple narrative beats that need production communication. For storyboard and shot-board, infer panel_grid_size from 2–16 irreducible narrative beats; never sample mechanically by duration or apply the project default of 4 to every shot. Use the project default shot-board/4 only when valid decision inputs are unavailable. overflow_strategy is compose-assets or reject and defaults to compose-assets. The storyboard image occupies the first image slot. If other images exceed the remaining provider slots, compose-assets deterministically combines them in reference order into one other-refpack-epNNN-NNN asset while preserving all sources; reject blocks the shot and adds the shortage to unresolved.
10. Tailor review_checks to actual shot risk: dialogue checks speaker identity and every visible mouth state; group shots check headcount, order, facing, and limb ownership; prop interaction checks before/contact/after states and adjacent objects; walking or fights check foot contact, weight, direction, speed, and pose across cuts; in-frame screens check whether precise post-production graphics are required. Never copy one generic checklist onto every shot.

No API key, token, remote business ID, Markdown, or explanation.
