# Codex 执行合同：production_plan

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

只返回严格 JSON：{"episode_key":"...","source_versions":{},"shots":[...],"totals":{},"unresolved":[],"approved":false}。

每个 shots 项必须包含：shot_number、dependencies、image_strategy、video_strategy、audio_strategy、provider、model_or_workflow、prompt_profile、input_mode、duration_seconds、resolution、aspect_ratio、candidate_count、reference_assets、estimated_paid_calls、fallback、review_checks、status。image_strategy 必须包含 mode、board_type、panel_grid_size、overflow_strategy。

规则：
1. 只能引用账本中存在的本地稳定 key 和 selected version；缺失或错版写入 unresolved。
2. 只选择 Provider 声明支持的模态和参数；不得猜测模型、工作流或费用。
3. 文本提示词由 Codex 生成，不列入外部文本模型调用。
4. totals 汇总各模态任务数、付费调用次数和已知预算；未知费用明确标 null。
5. unresolved 非空、预算未确认、参考素材用途未确认或任何付费参数缺失时，approved 必须为 false。
6. status 初始只能是 blocked 或 ready；依赖不齐不得写 ready。
7. prompt_profile 只能是 seedance2、h3 或 generic；input_mode 必须是所选模型真实支持的输入模式。Seedance 2.0 参考素材要固定类型、用途和提交顺序；H3 必须区分 T2VA、I2VA、FL2VA、L2VA 与 Ref2VA。无法判定时写入 unresolved。
8. Provider 明确支持 MiniMax H3 原生音频时，audio_strategy.mode 写 native，并记录逐秒 speech_timeline、跨镜统一 music_anchor 和相邻镜 transition_pair；这类镜头不得另排 TTS。能力未明确、用户要求后配或模型不支持时写 post-dub/independent，并排入独立音频流程。相邻 H3 镜头的 transition_out 与 transition_in 必须成对一致。
9. image_strategy.mode 固定为 generate，每一镜都必须先生成分镜图。board_type 只能是 single、storyboard 或 shot-board：静态构图、单一决定性瞬间或首帧锚点选 single，panel_grid_size 固定为 1；同一连续镜头需要多个时间关键帧、动作阶段或运镜轨迹选 storyboard；多人调度、对白反应、轴线、复杂动作或现场沟通多个叙事节拍选 shot-board。落档前必须先读本分镜构图合同（visual_plan.composition、composition_contract 或 photographyPlan.composition 的 primary/secondary code、evidence、ai_risks；受控码与风险码见 references/controlled-vocabulary.json 的 cinematography.compositionPatterns 与 references/director-composition.md 0.4）：静态单一情绪、单一决定性瞬间且无动作阶段或运镜变化坚持 single；追逐、跃起、冲接触、贴身搏斗、余势收镜等要在一镜内展示动作阶段或运镜轨迹变化用 storyboard 按阶段定格；多人站位与朝向几何、对峙或桌边谈判、三人关系三角、包围/前后夹击/群体冲锋、依赖前景遮挡或窄门缝阅读、武器持有或接触动作、多手道具交互用 shot-board，按人数、视线网、蓄力—接触—结果拆格。ai_risks 风险只决定格数与回退，不得用加格替代证据。证据门为 OR，先于板型：evidence 需要 set_dressing、weather_atmosphere、action_blocking 等级（复合证据以 + 连接时逐组件成立）；set_dressing、weather_atmosphere 必须在原文明确描述或已选场景/道具资产中有据，action_blocking 还可由已确认调度事实支撑，但已确认调度事实不能替代天气/陈设所需的原文或资产证据。所需证据均无据时，status 写 blocked，把所缺证据与构图 code 写入 unresolved 并退回 revise-drama-storyboards 补证据或更换构图，不得排产；媒体模板对无证据高风险元素同样停止出片并退回分镜，禁止靠板型或提示词措辞绕过。storyboard 与 shot-board 的 panel_grid_size 由你按不可合并的叙事节拍判断为 2–16，不按时长机械抽帧，也不机械套用项目默认 4 格。项目默认 shot-board/4 格只在有效判断输入不足时回退。overflow_strategy 只能是 compose-assets 或 reject，默认 compose-assets。分镜图优先占一个图片槽位，其他图片超过剩余槽位时，compose-assets 将其按引用顺序确定性拼成一张 other-refpack-epNNN-NNN 合板且不得丢失来源，reject 则阻塞并写入 unresolved。
10. review_checks 按逐镜真实风险填写，每个检查项必须是具体、具名、可观察的短语（如「镜面反射一致性」「雨幕接触点可读」），并从合同 ai_risks 与证据元素反推：对白检查说话人与每张可见嘴部状态；多人镜检查人数、顺序、朝向和肢体归属；道具交互检查接触前/中/后状态及邻接物；步行/打斗检查落脚、重心、方向、速度和跨镜姿态；画内屏幕检查是否需要后期精确图形。命中构图风险时必须逐项落为检查：镜面/光滑水面核对映像与真人及现场陈设一致、无多指、无多余摄像机或反射穿帮；雨、雾、霓虹、烟尘核对天气光色有据、雨丝/烟向统一且不淹没接触点与人物身份；群体镜核对人数、身份、服色锚点且无多余路人；武器与多手交互核对形制、持有关系、手数与接触前/中/后；窄门缝或前景遮挡核对可见宽度、双眼完整与关键动作不被盖；高速拖影核对双眼、面部与接触点清晰可辨、主体不糊；前后夹击/包围核对前后景两方身份、距离与朝向可辨；竖屏镜核对脸、关键道具与接触点在中上安全区、底部字幕安全区不被占、动势边缘留 10% 余量。只保留本镜命中的风险项，不得复制同一组空泛检查覆盖所有镜头。

禁止 API Key、Token、远程业务 ID、Markdown 和解释。
