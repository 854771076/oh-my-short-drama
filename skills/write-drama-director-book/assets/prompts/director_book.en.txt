# Codex execution contract: director_book

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

Execution role: short-drama director. Turn the selected screenplay into a scene-level directing contract that explains why each scene is staged this way, without pre-allocating final shot numbers.

[PROJECT AND DELIVERY CONTRACT]
{project_contract}

[STORY BIBLE]
{story_bible}

[SELECTED EPISODE SCREENPLAY]
{screenplay}

Return strict JSON only: {"episode_key":"...","source_script_version":"...","scenes":[...],"continuity_ledger":[],"open_questions":[]}.

Every scenes item contains: scene_key, source_scene, dramatic_objective, beats, subtext, performance_direction, blocking, eyelines, axis_rule, camera_strategy, lighting_and_color, sound_plan, transition_in, transition_out, continuity_state, asset_requirements, prohibited_changes.

Rules:
1. Map every scene to the screenplay and cover it completely. Never add plot facts or rewrite verbatim dialogue.
2. Read backward from the scene ending's change in information, relationship, or power to name one shared scene event. dramatic_objective must include every present character, including silent ones, as a participant; it is a playable relational action, not a theme or intended audience effect.
3. For each character, performance_direction states their motive for participating in that event, current objective, obstacle, tactic, listening/eyeline target, and an evidenced physical channel. Give silent characters a playable task such as assessing, concealing, waiting for an opening, or protecting the situation. When the screenplay already contains ongoing work or daily business, let the tactic travel through it and use an evidenced interruption as a beat accent. subtext states the gap between words and intent. Never replace behavior with vague emotion or invent actions to fill fields.
4. blocking, eyelines, and axis_rule agree and specify start/end positions and movement direction. Tie approach, retreat, occupation of space, and status reversal to a specific beat and relationship change; avoid unmotivated movement and false measurement precision the model cannot render reliably.
5. sound_plan separates dialogue, voiceover, ambience, action sound, and BGM intent without inventing final audio parameters.
6. continuity_ledger tracks persistent appearance, prop state, screen direction, time, and lighting across scenes. When a character exits frame, also record the exit edge, last visible posture, movement direction, and held props until that character re-enters or the scene explicitly resets; re-entry must agree with that record and the established axis.
7. Put any new decision affecting plot meaning, relationships, or sound policy in open_questions.

No final shot numbers, generation models, cost, image prompts, Markdown, or explanation.
