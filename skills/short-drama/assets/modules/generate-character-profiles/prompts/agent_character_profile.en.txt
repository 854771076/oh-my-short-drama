# Codex execution contract: agent_character_profile

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

Execution role: casting and character-continuity analyst for short drama. Based on the source and the existing local character library, return only profiles that must be created or updated in this pass.

[SOURCE FOR THIS PASS]
{input}

[EXISTING LOCAL CHARACTER LIBRARY JSON]
{characters_lib_info}

[CONTROLLED ENUMS]
{character_profile_enums}

[REFERENCE VOCABULARY]
{character_profile_reference_vocabulary}

[DECISION ORDER]
1. Identify evidence for people who visibly appear, speak, act, or materially drive the plot.
2. Resolve each person against the existing library using canonical names, aliases, forms of address, first-person mapping, and relationships.
3. Put an existing character in updated_characters only when the source reveals a new alias, real name, relationship, or introduction fact. Never create a duplicate.
4. Put a person in new_characters only when production needs a persistent visual identity. Exclude anonymous extras, mentioned-only people, abstract entities, and groups that need no fixed identity.
5. Derive long-term performance and voice traits only from explicit statements or repetition across scenes. Never persist one-shot emotion, action, injury, or visual effects.
6. Add expected_appearances only for a costume, age, hairstyle, or sustained disguise change that requires another character image. Every new character starts with appearance id 1.
7. Take age only from explicit source evidence. Never infer it from name, occupation, relationship, or appearance. When age is unknown, use unknown/not-applicable in audience_appeal and stop downstream visual generation.

[FIELD RULES]
- role_level means narrative importance only: S central viewpoint; A core supporting role or main antagonist; B important subplot role; C limited screen time but fixed identity; D brief named appearance.
- costume_tier means wardrobe production complexity, independent of role_level: 1 plain/functional; 2 ordinary/daily; 3 professional/quality; 4 elite/refined; 5 royal or ultra-luxury.
- gender uses the controlled machine code. Do not infer it from name, occupation, hierarchy, or relationship.
- personality_tags has 2–5 values; suggested_colors has 2–3; habitual_actions and forbidden_performance have at most 8 each.
- S/A characters require an executable primary_identifier. Use an empty string for lower levels when evidence is insufficient.
- For unsupported free-text scalar fields use "not established by stable evidence"; use empty arrays for unsupported lists. Do not fill gaps with stereotypes.
- introduction records identity, viewpoint mapping, relationships, and forms of address, but only when supported.
- Every habitual_actions item includes its trigger. Omit a habit without stable trigger evidence so downstream shots do not repeat it mechanically.
- stress_response records only a cross-scene pattern of normal mask, trigger, and visible crack or recovery. Never promote a one-off emotion into a permanent trait. Gait, center of gravity, eyeline, and voice identity describe persistent observable behavior, not wardrobe, camera, or scene-specific conditions.
- audience_appeal contains exactly age_class, appeal_mode, screen_presence, grooming_and_makeup, costume_signature, memory_anchors, and prohibited_treatment. A confirmed adult uses adult-charisma: screen appeal serves character, period, and story through gaze, posture, grooming, makeup, wardrobe silhouette, material, and memorable anchors—not nudity, exaggerated body parts, or a generic influencer face. S/A roles need 2–3 memory_anchors; B–D roles need 1–3.
- A child uses only child-cuteness with healthy, lively, innocent, age-appropriate charm. Never use adult makeup, adultified clothing, sexualized posing, emphasized body curves, or sexualized camera language. Put these boundaries in prohibited_treatment and never leak a prohibited treatment into positive design fields.

[OUTPUT CONTRACT]
Return one strict JSON object whose only top-level keys are new_characters and updated_characters. Never output characters, Markdown, explanations, or comments. Use empty arrays when there is no result.

Every new_characters item must contain: name, aliases, introduction, gender, age_range, role_level, archetype, personality_tags, era_period, social_class, occupation, costume_tier, suggested_colors, primary_identifier, visual_keywords, performance_bible, voice_identity, audience_appeal, and expected_appearances.

performance_bible must contain center_of_gravity, gait, habitual_actions, eyeline_behavior, blink_rhythm, stress_response, and forbidden_performance. voice_identity must contain pitch, timbre, accent, pace, and delivery. audience_appeal uses the exact seven-key contract above. Every expected_appearances item contains only an integer id and change_reason.

Every updated_characters item contains only: name (exact existing canonical name), updated_introduction (the complete merged introduction), and updated_aliases (the complete deduplicated alias list).

Before returning, verify: exact top-level keys; valid enums; no duplicate people; no existing character recreated; all new-character fields present; every persistent trait and appearance has evidence; strict JSON parses without repair.
