【构图受控词表】
{cinematography_vocabulary}
下列词表是逐镜构图词汇，导演本只在场次层使用：每场仅从中选取 1–3 个 code 作为场级构图母题，不逐镜分配构图，也不要求下游机械沿用。名称与 code 的完整对照、逐模式证据要求与竖屏规则见 references/controlled-vocabulary.json 的 cinematography.compositionPatterns 与 references/director-composition.md；本合同只使用其 code。

只返回严格 JSON：{"episode_key":"...","source_script_version":"...","scenes":[...],"continuity_ledger":[],"open_questions":[]}。

每个 scenes 项必须包含：scene_key、source_scene、dramatic_objective、beats、subtext、performance_direction、blocking、eyelines、axis_rule、action_complexity、camera_strategy（含 composition_motifs）、lighting_and_color、sound_plan、transition_in、transition_out、continuity_state、asset_requirements、prohibited_changes。action_complexity 只能是 ordinary 或 choreographed。

规则：
1. 每个场次逐一对应剧本场景并完整覆盖；不得新增剧情事实或改写逐字台词。
2. 先从场尾的信息、关系或权力变化反读本场共同事件，把所有在场人物（包括沉默者）纳入 dramatic_objective；它描述本场正在发生的关系行动，不写成主题口号或观众效果。
3. performance_direction 按角色写清参与共同事件的个人动机、当前目标、阻力、策略、倾听/视线对象和有来源证据的身体通道。沉默角色也要有可表演任务，例如判断、隐瞒、等待破绽或维持局面；若剧本存在持续工作或生活动作，让角色通过该动作完成策略，停止动作可作为节拍重音。subtext 说明言语与真实意图的差距，不用空泛情绪代替行为，也不为凑字段补造动作。
4. blocking、eyelines 和 axis_rule 必须互相一致，明确人物起止位置和运动方向；接近、退让、占据空间或地位翻转必须对应具体节拍与关系变化，不做无动机走位，也不使用模型无法稳定兑现的伪精确距离。
5. camera_strategy 必须包含 composition_motifs：1–3 个场级构图母题的数组，每个母题是且只能是以下形状的对象：{"code":"...","narrative_job":"...","variation":"...","payoff":"...","axis_constraints":"..."}。code 只能是受控词表 code（composition.basic.* / composition.film.* / composition.action.* / composition.character.*）；narrative_job 写该母题的叙事职责；variation 写它随本场共同事件如何变化（例如同一构图在进入、翻转、场尾的不同用法）；payoff 写它在场尾如何回收；axis_constraints 写它对相邻镜屏幕方向、视线与轴线的约束。母题是场级视觉意图，不是镜号清单，也不是逐镜构图分配；禁止在导演本预拆最终镜号或要求下游机械轮换。选择 code 即承诺满足其证据门槛：composition-only 仅靠机位、景别、调度与曝光实现，不向画面添加原文或资产之外的物件与天气；set_dressing 所需门窗、镜、廊柱、长桌、霓虹、武器等必须能在剧本描写或场景/道具资产中成立；weather_atmosphere 的雨、雪、雾、逆光或双色温光源必须在原文、场次时段或资产中有依据；action_blocking 的冲突、追逃、包围、群体走位必须由剧本或导演调度支持；以 + 连接的复合证据每个组件都必须满足。证据不足时改用低门槛母题，不得靠想象补陈设、道具或天气。
6. sound_plan 区分对白、旁白、环境声、动作声和 BGM 意图，但不伪造最终音频参数。
7. continuity_ledger 记录跨场持续的人物造型、道具状态、空间方向、时间和光线。人物离画时还要记录离画边、最后可见姿态、运动方向和持物状态，保留到其下一次入画或场景明确重置；重新入画方向必须与该记录和既定轴线相容。
8. 涉及剧情含义、人物关系或声音策略的新决定写入 open_questions。
9. 只有场次需要跨镜动作连续性、接触与受力结果、兵器、追逐、擒抱、跌倒、多人攻防或能力战设计时，action_complexity 才写 choreographed；普通争吵、静态对峙、走路、握手、推门和简单拿放道具写 ordinary。扇耳光、推搡和短暂拉扯只有需要专业动作编排时才写 choreographed，不得为触发模块夸大复杂度。

禁止最终镜号、生成模型、费用、图片提示词、Markdown 和解释。
