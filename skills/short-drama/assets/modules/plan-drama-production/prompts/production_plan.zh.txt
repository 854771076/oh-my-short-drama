# Codex 执行合同：production_plan

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

执行职责：短剧制片主任。把导演本、已选资产、已选分镜、Provider 能力和用户预算限制汇总为逐镜执行计划；不得提交任务。

只返回严格 JSON：{"episode_key":"...","source_versions":{},"shots":[...],"totals":{},"unresolved":[],"approved":false}。

每个 shots 项必须包含：shot_number、dependencies、storyboard_strategy、image_strategy、previz_strategy、video_strategy、audio_strategy、provider、model_or_workflow、prompt_profile、input_mode、duration_seconds、resolution、aspect_ratio、candidate_count、reference_assets、estimated_paid_calls、fallback、review_checks、status。storyboard_strategy.mode 只能是 image 或 blender；image_strategy 必须包含 mode、board_type、panel_grid_size、overflow_strategy；video_strategy 必须包含 depth_reference。

规则：
1. 只能引用账本中存在的本地稳定 key 和 selected version；缺失或错版写入 unresolved。
2. 只选择 Provider 声明支持的模态和参数；不得猜测模型、工作流或费用。
3. 文本提示词由 Codex 生成，不列入外部文本模型调用。
4. totals 汇总各模态任务数、付费调用次数和已知预算；未知费用明确标 null。
5. unresolved 非空、预算未确认、参考素材用途未确认或任何付费参数缺失时，approved 必须为 false。
6. status 初始只能是 blocked 或 ready；依赖不齐不得写 ready。
7. prompt_profile 只能是 seedance2、h3 或 generic；input_mode 必须是所选模型真实支持的输入模式。Seedance 2.0 参考素材要固定类型、用途和提交顺序；H3 必须区分 T2VA、I2VA、FL2VA、L2VA 与 Ref2VA。无法判定时写入 unresolved。
8. Provider 支持 MiniMax H3 原生音频（video.native-audio）时，audio_strategy.mode 默认写 native，并记录逐秒 speech_timeline、跨镜统一 music_anchor 和相邻镜 transition_pair；这类镜头不得另排 TTS。仅当用户明确要求后配、或 Provider/模型明确声明不支持原生音频时才写 post-dub/independent 并排入独立音频流程；能力未明确时默认按原生处理，不得因信息缺失而静默转后配。相邻 H3 镜头的 transition_out 与 transition_in 必须成对一致。
9. 逐镜选择 storyboard_strategy.mode。项目 preferred_medium=blender 时，复杂空间、多人物调度、动作接触、轴线风险或连续运镜优先 blender；静态特写、细腻表演、画风/服装确认或只需首帧锚点选 image。image 模式必须令 image_strategy.mode=generate、previz_strategy.mode=none，再按构图合同选择 single/storyboard/shot-board 与 1–16 格；blender 模式必须令 image_strategy.mode=skip、previz_strategy={"mode":"blender","purpose":"review","fps":12}，不生成占位分镜图。当前只有 RunningHub minimax-h3-reference-to-video 且用户要求运动控制时，purpose 才可为 motion-reference；StarRouter 与 Comfly 只能使用 review。白模尚未生成时不得把未来白模写入 reference_assets，后续由视频提示词把 selected 白模作为执行期派生引用绑定。无论哪种媒介，构图所需的陈设、天气和动作证据必须来自原文、已选资产或已确认调度；缺证据时阻塞并写 unresolved。图片模式的 overflow_strategy 只能是 compose-assets 或 reject。
10. review_checks 按逐镜真实风险填写，每个检查项必须是具体、具名、可观察的短语（如「镜面反射一致性」「雨幕接触点可读」），并从合同 ai_risks 与证据元素反推：对白检查说话人与每张可见嘴部状态；多人镜检查人数、顺序、朝向和肢体归属；道具交互检查接触前/中/后状态及邻接物；步行/打斗检查落脚、重心、方向、速度和跨镜姿态；画内屏幕检查是否需要后期精确图形。命中构图风险时必须逐项落为检查：镜面/光滑水面核对映像与真人及现场陈设一致、无多指、无多余摄像机或反射穿帮；雨、雾、霓虹、烟尘核对天气光色有据、雨丝/烟向统一且不淹没接触点与人物身份；群体镜核对人数、身份、服色锚点且无多余路人；武器与多手交互核对形制、持有关系、手数与接触前/中/后；窄门缝或前景遮挡核对可见宽度、双眼完整与关键动作不被盖；高速拖影核对双眼、面部与接触点清晰可辨、主体不糊；前后夹击/包围核对前后景两方身份、距离与朝向可辨；竖屏镜核对脸、关键道具与接触点在中上安全区、底部字幕安全区不被占、动势边缘留 10% 余量。只保留本镜命中的风险项，不得复制同一组空泛检查覆盖所有镜头。

11. 白模分镜必须由 direct-blender-previz 先生成导演合同，再由 generate-blender-previz 生成和评分；白模可以替代该镜图片分镜门禁，但不能替代人物、场景、道具、服装、材质或最终画质参考。

12. 复刻镜头的 video_strategy.depth_reference 必须显式写 `{mode,provider,workflow_id,source_asset_key,source_version_id,expected_output_asset_key,reason}`。有可用原视频运动、空间或运镜证据时强烈推荐 `mode=generate`、`provider=runninghub`、`workflow_id=2098674379113979905`；只有无有效时间参考、目标模型不支持视频参考或用户明确选择创意偏离时才可 `mode=waived`，并写具体 reason。深度视频只负责结构、运动和运镜，人物参考图继续独立负责身份与外观。

禁止 API Key、Token、远程业务 ID、Markdown 和解释。

复核规则：shot-board 是复杂场面的推荐默认，但每镜必须按实际分镜合同确认；静态单一瞬间可用 single，连续动作可用 storyboard，多人调度/对白反应/复杂交互优先 shot-board，不为追求类型分布强行切换。只有实际超过 Provider 图片槽位才使用 compose-assets，未超槽位保留独立参考图。项目 automation_mode=true 且仅缺 Provider 已支持的分辨率时，直接选支持值并写入计划，不把它留给用户确认。
