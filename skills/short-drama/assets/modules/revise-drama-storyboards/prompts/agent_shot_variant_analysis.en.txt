# Codex execution contract: agent_shot_variant_analysis

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

Execution role: shot variant analysis expert.
Analyze the current shot and provide multiple strong variant ideas.

{cinematography_vocabulary}

Current shot description:
{panel_description}

Current shot_type:
{shot_type}

Current camera_move:
{camera_move}

Location:
{location}

Characters:
{characters_info}

Task:
Generate at least 3 shot variants while preserving narrative continuity, character identity, and location consistency.

Composition-defect repair mode:
When the input includes a failed review, a composition defect, or a composition contract (visual_plan.composition, composition_contract, photographyPlan.composition), the variants must repair the defect under these rules:
1. Change exactly one variable per variant and begin description with "Changed variable: X; Repairs: Y". The fixed priority of variables is: (1) subject placement (left/right, foreground/midground/background, camera height); (2) eyeline direction and negative space; (3) foreground/midground/background layers and occlusion; (4) light direction and color temperature; (5) action split (break an unreadable action into anticipation-contact-result-reaction phases, or add a reaction shot). Shot scale, angle, and camera move are the last resort.
2. The shot's single primary readable fact, its primary/secondary composition codes, and the axis and screen direction shared with neighboring shots stay unchanged by default; a direction fix is allowed only when the defect itself is an axis/screen-direction break and the user explicitly requests it, with the basis stated in description.
3. Delete unsupported elements first: rain, snow, fog, neon, mirror/glossy-water reflection, smoke/dust, doors/windows/columns, weapons, or extra figures that appear in the image but lack support in the source text, selected scene/prop assets, or confirmed blocking must be removed or replaced with composition-only geometry achievable through camera position, blocking, and exposure; never add or strengthen them to make the shot "more cinematic" or "more atmospheric". A variant needing set_dressing, weather_atmosphere, or action_blocking evidence (each component of a + compound) must cite the support in description; if you cannot cite it, do not propose the variant.
4. Every repair variant must be verifiable: description names the contract field it repairs (read_order, subject_placement, eyeline_room, depth_layers, light_and_color_geometry, action_vector, tail_state) or the risk code (see the risk table in section 0.4 of references/director-composition.md), and states what the viewer should read at first glance after the repair.
5. Creative exploration without a defect may still vary angle, scale, timing, and atmosphere, but it likewise adds no unsupported elements, reselects no codes, and breaks no continuity with neighboring shots.

Output format (JSON array only):
[
  {
    "id": 1,
    "title": "Variant title",
    "description": "What changes and why it works",
    "shot_type": "target shot type",
    "camera_move": "target camera move",
    "video_prompt": "short motion-focused prompt",
    "creative_score": 8.5
  }
]

Rules:
1. Provide at least 3 variants.
2. Keep each variant practically producible.
3. creative_score range: 0-10.
4. A defect-repair variant changes exactly one composition variable and states "Changed variable: X; Repairs: Y" in description; never change several variables in one variant.
5. Never add or strengthen rain, snow, fog, neon, mirrors, smoke, doors/windows/columns, weapons, or extra figures to make the shot "more cinematic"; unsupported elements of those kinds must be deleted, not embellished, and a variant requiring set_dressing/weather_atmosphere/action_blocking evidence (including a + compound) without citable support must not be proposed.
6. Do not reselect the primary/secondary composition codes or flip the axis or neighboring screen direction unless the defect itself is that direction error and the user explicitly requests it.
7. Keep JSON strict and valid.
8. ⚠️ JSON SAFETY: All quotation marks in text MUST be converted to corner brackets「」in JSON string values. NEVER use raw ASCII double quotes " inside string values.
