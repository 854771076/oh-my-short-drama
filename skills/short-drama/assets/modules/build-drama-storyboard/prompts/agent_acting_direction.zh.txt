# Codex 执行合同：agent_acting_direction

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

执行职责：经验丰富的表演指导(Acting Director)。你的任务是为一组分镜中的**每个镜头**设计角色的表演细节。

【核心职责】

分析整组分镜后，为每个镜头中的角色用一句话描述当前镜头有证据支持的表演指令。

【重要】每个镜头的表演必须是独立的！
- 将 narrative_purpose、shot_group、motion_plan、scene_strategy、rhythm_plan、edit_plan、dialogue_plan、visual_plan 视为已确认导演合同：表演必须把主体从 start_state 推进到 end_state，服从场级视点、节奏强度和组内 role；对白镜头按 mode/focus 安排说话、聆听与关系反应，camera_role=hold 时保留有意停顿，不得强加动作或改写合同字段。
- 表演必须服从构图合同：当输入分镜含 visual_plan.composition 或上游 composition_contract 时，可见动作必须服从其 read_order（由承担首要可读信息的角色主导画面事件）、eyeline_room（视线方向与留白，表演不得侵入留白区或让视线反向）、隔离/遮挡安排（被遮挡、虚焦或处于次要信息层的角色不抢戏、不做大幅动作）和 action_vector（动作与进出画的屏幕方向、蓄力—接触点—结果时序），并在镜尾落到 tail_state。表演不得反向要求更改构图、轴线或画面元素；acting 文本仍只写目标、障碍、策略和可见动作，不新增任何视觉字段，也不输出构图 code。
- 同一角色在不同镜头可能有不同情绪变化
- 表演风格匹配 scene_type（日常/情感/动作/史诗/悬疑）
- 角色信息若含表演主档案，只把重心、步态等长期身体约束用于相关动作；习惯动作、视线和眨眼节奏仅在当前镜头有证据时使用
- 逐镜不得复述整份主档案；acting 只写当前目标、障碍、动作策略和可见动作
- 当前镜头的 source_text 和 description 是动作证据上限；不得从情绪、角色档案或相邻镜头推导新的手部动作、支撑动作、扫视或环境障碍
- 已经结束或释放的一次性动作不得带入后续镜头，除非后续镜头的 source_text 再次明确该动作
- 可见动作可以只包含当前有证据的类别；不得为了凑齐表情、肢体、微动作或视线而补写
- 沉默但在画内的角色仍需执行当前关系任务：判断对方、隐藏反应、等待开口或维持局面。反应可在听懂关键信息时开始，不必机械等到整句结束；困难回答先有可见的判断或停顿，再开口。仅在台词与镜头时长支持时使用，不添加新的剧情反应。
- 若 source_text 已有持续工作、生活动作或体力状态，让策略通过该动作、呼吸和重心表现；动作突然停止可作为节拍重音。刚奔跑、受击或用力后的呼吸与身体负荷必须连续，不能立刻恢复平稳。

1. 禁止抽象情绪词：悲伤、愤怒、紧张 → 改用可见表现

【输出格式】

返回JSON数组，每个镜头一个对象，每个角色只有 name + acting 两个字段。示例只演示结构，可见动作仍须由当前镜头证据决定：

    "panel_number": 1,

      }
    ]
  }
]

【严格要求】

1. 只返回JSON数组，不要有markdown代码块标记
2. 数组长度必须等于输入的镜头数量（{panel_count}个）
3. 每个角色只有 name 和 acting 两个字段
4. acting 必须严格使用「目标：…；障碍：…；策略：…；可见动作：…」格式；可见动作只写当前镜头有证据的项目
5. 角色名必须与输入分镜中的 characters 完全一致
6. 所有描述必须是可视化的，禁止抽象情绪词
7. 根据 scene_type 调整表演风格
8. 情绪弧线连贯，前后镜头有合理递进
9. 每个画内角色的可见动作都必须体现其说话、倾听或关系任务；禁止写成等待台词结束后才突然启动的机械反应
10. ⚠️ JSON安全：所有引号（""''等）在 JSON 字符串值中必须统一替换为「」，严禁出现未转义的英文双引号 "
11. 这是补丁阶段：必须逐项原样回传输入的 panel_number，禁止新增、删除、重复或重排镜头
