# Codex execution contract: drama_brief

The owning Skill reads this file to constrain Codex inputs, decisions, and output. It is not a system prompt sent to an external text model. Braced fields are named input slots assembled from selected local project assets.

Execution role: short-drama production planner. Turn the source analysis and user decisions into an executable, confirmable creative brief without inventing unresolved parameters.

[SOURCE ANALYSIS]
{source_analysis}

[USER-CONFIRMED DECISIONS]
{user_decisions}

[USER-SELECTED MARKET INSPIRATION]
{market_inspiration}

[RECREATION CONSTRAINT PACKS (viral-recreation only)]
{recreation_compiled}

Return strict JSON whose only top-level keys are: title, logline, adaptation_mode, genre, audience, platform, tone, core_conflict, output_language, spoken_language, subtitle_language, aspect_ratio, episode_count, episode_duration_seconds, rating, existing_materials, required_deliverables, prohibited_content, ending_type, creative_constraints, market_inspiration_ref, open_questions, approved. Only `viral-recreation` projects also include recreation_workflows.

Rules:
1. Put every unresolved parameter that changes the creative result in open_questions, use null for its field, and set approved to false.
2. Use BCP 47 language tags and record output text, spoken dialogue, and subtitle language separately.
3. Never choose episode count, duration, aspect ratio, platform, rating, or ending type from convention. episode_duration_seconds is a planning target, not an exact frame-level cutoff; treat it as a hard maximum only when the platform explicitly imposes one.
4. Keep adaptation_mode consistent with source-analysis and record adaptation boundaries in creative_constraints.
5. approved may be true only after open_questions is empty and the user has confirmed the whole brief.
6. Write market_inspiration_ref only when the user explicitly selects market inspiration, preserving that inspiration artifact's complete report_ref exactly; otherwise use null. This reference cannot override source facts, compliance requirements, or user-confirmed decisions.
7. Write recreation_workflows only for `viral-recreation` projects, binding every episode exactly to its selected recreation constraint-pack version; standard projects must omit this field.

No Markdown, explanation, screenplay content, or model parameters.
