# Codex 执行合同：episode_split

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

执行职责：短剧分集策划。根据已确认的 brief、故事圣经和来源边界，生成完整分集目录。

【输入】
{CONTENT}

规则：
1. 严格使用 brief 中确认的总集数；单集时长以目标值为中心规划，不按固定字数自行推算集数，也不为精确卡秒破坏动作、对白或钩子。默认实际成片可在目标值约 ±15% 内自然浮动；超出不自动判失败，但必须记录叙事原因并重新请用户确认。
2. 每集必须带来新的行动、信息、关系变化或代价；不得仅重复上一集情绪。
3. opening_connection 明确承接上一集；episode_goal 给出本集主动目标；turning_point 改变局势；ending_hook 产生下一集必须回答的问题或行动。
4. 按故事圣经兑现冲突阶梯、伏笔和回收。不得提前消耗最终高潮，也不得遗漏结局所需铺垫。
5. 改编项目用 source_range 记录本集覆盖的原文起止锚点；必须按顺序完整覆盖且不得重叠。原创项目可将 source_range 设为 null。
6. required_assets 只列本集实际需要的人物、场景和关键道具规范名，不写视觉描述或模型参数。
7. episode key 固定为 ep-001、ep-002……，order 从 1 连续递增。

只返回严格 JSON：
{
  "episodes": [
    {
      "key": "ep-001",
      "order": 1,
      "title": "集名",
      "logline": "本集一句话因果",
      "opening_connection": "如何承接上一集或建立首集",
      "episode_goal": "人物本集主动目标",
      "beats": ["可见行动或信息节拍"],
      "turning_point": "不可省略的局势变化",
      "payoff": "本集兑现",
      "ending_hook": "下一集钩子",
      "source_range": {"start_marker": "逐字锚点", "end_marker": "逐字锚点"},
      "required_assets": {"characters": [], "scenes": [], "props": []},
      "estimated_duration_seconds": 90
    }
  ],
  "coverage_check": {"complete": true, "gaps": [], "overlaps": []},
  "continuity_check": {"valid": true, "issues": []}
}

禁止 Markdown、解释和额外字段。输出前核对集数、key、order、原文覆盖、钩子承接、伏笔回收和总时长。
