# Codex 执行合同：select_location

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

从原文提取需要跨镜复用的场景资产。场景是可稳定复现的空间，不是镜头动作或人物表演。

【原文】
{input}

规则：
1. 只提取真实发生戏份或明确将进入的空间；同地点的房间/区域仅在存在明确包含关系时放入 sub_locations。
2. 每个场景给出三条构图不同但结构一致的静态描述；保留时代、建筑、材质、固定陈设、前中后景、光源方向和至少三个稳定锚点。
3. 每个场景给 2–6 个 available_slots，必须以描述中真实锚物定位，不写人物动作。
4. 默认生成人物空镜。只有原文明示且场景语义离不开公共人群时，才设 has_crowd=true，并只写无名、非主体背景人群；不得出现具名角色。
5. 原文缺失的尺寸、层数、天气、设施和装饰只做最小中性补全，不制造事实。过泛地点要具体化到可控布局，但不得借机扩写剧情。

只返回严格 JSON：{"locations":[{"name":"稳定场景名_时间","summary":"空间用途","has_crowd":false,"crowd_description":"","available_slots":["锚物与方位明确的位置"],"descriptions":["静态描述一","静态描述二","静态描述三"],"sub_locations":[]}]}。无场景返回 {"locations":[]}；使用标准 JSON 转义，不要额外字段。
