# 编导 Blender 白模预演

只处理制作计划中 `previz_strategy.mode=blender` 的镜头。读取当前 selected 剧本、导演本、结构化分镜、制作计划和人物/场景/道具选版；若该镜选择图片分镜，再读取 selected 分镜图和八维审计。白模分镜模式不把图片分镜设为前置条件，也不凭文字单独猜测资产已定义的三维空间。

信息优先级固定：剧本和导演本决定因果与表演先后，结构化分镜决定时间和连续动作，人物/场景/道具选版约束身份与空间；图片分镜存在时只锚定构图与屏幕方向。白模负责验证三维距离、遮挡、接触、节奏和相机路径。冲突时退回上游澄清，不用白模悄悄改剧情。

为每镜确定唯一首要可读信息，再拆成带帧号的发现、反应、行动、介入、接触/阻断、结果和镜尾状态。人物调度必须记录起止位置、朝向、视线、入出画边、前后层次、行走区间和关节动作；多人镜保持身份、左右顺序和动作归属可辨。对白、对峙或攻防接管不能只依赖一个移动主镜头：叙事需要拆开意图与反应时，优先使用建立镜头、正打、反打、双人接触镜头和结果反应镜头。正反打全部保持在同一轴线侧，匹配人物视线、屏幕方向、头部留白和近似景别，切点落在动作启动、视线接管或反应开始处，不在接触瞬间破坏可读性。即使以单人为主体，也必须让对象通过同框、过肩、明确视线或相邻镜头关系可辨；合同写了对象或反应不算完成，必须在实际画面中看见。单个机位只保留一个有叙事动机的主运动，写明起止构图、焦段、机位高度、目标点、加速、减速和停稳帧；关键帧用缓入缓出，接触或揭示前完成减速并留出可读停顿。除非有明确视觉目的，不同时叠加变焦、推拉、横移和环绕。

白模作为正式视频运动参考时，合同 `duration_seconds` 必须与当前制作计划该镜 `duration_seconds` 完全一致，所有节拍和镜尾停稳必须覆盖完整时长；不得用三秒动作摘要替代八秒镜头。若台词尚未配音，也要为说话表演、反应停顿和可剪辑镜尾分配明确帧段。

按 [白模导演合同与评分](direct-blender-previz/direction-contract.md) 输出与 `scripts/blender-previz.py` 兼容的 JSON，保存为 `episodes/<episode-key>/previz/shot-<NNN>-vNNN.json`。合同必须包含当前分镜与制作计划版本、剧情意图、覆盖首帧到镜尾且无空档、无倒序或过度重叠的节拍表、轴线与屏幕方向、相机动机、连续性和验收项；五项固定硬门禁不得删减。单机位使用 `camera`，正反打覆盖使用 `cameras` 与 `camera_cuts`，并配合 `objects`、人物 `walk`、根节点关键帧和 `arm_keyframes`。接触检查声明的帧不得同时作为机位切点；生成前必须通过脚本的合同结构校验，不能用文字约定替代可执行门禁。

镜头含武打、追逐、擒抱、跌倒、兵器或明确身体接触时，还必须读取 [动作白模编导门禁](direct-blender-previz/action-previz.md)。涉及兵器、常用灰模道具或修仙术法时，同时读取 [武器、灰模与术法预设](direct-blender-previz/weapons-vfx.md)。先验证当前骨架控制能否表现所需肢体链、落脚和接触；能力不足就停止并报告缺口，不用直臂、滑步或模型穿插冒充武打。没有真实剧本来源的能力测试必须标记 `test_only`，不得声称符合项目剧情。

交给 `generate-blender-previz` 渲染后完整观看，并在动作入点、接触点、完成点和镜尾逐帧复核。剧情因果、人数与身份、对白对象关系、轴线与屏幕方向、物理接触、关键物可见，以及剧本要求的镜尾反应必须在实际画面中可见；任一失败都不得用合同文字或总分抵消。全部通过、评分达到 85/100 且没有单项低于该项分值的 70% 才可进入正式视频；否则一次只改一个最可能变量并生成新合同、新视频版本。同一问题连续两次未改善就停止盲调，退回结构化分镜或导演本。
