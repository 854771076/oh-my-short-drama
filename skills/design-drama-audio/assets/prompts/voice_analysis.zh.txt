# Codex 执行合同：voice_analysis

本文件由所属 Skill 读取，用于约束 Codex 的输入、判断与输出；不是发送给外部文本模型的 system prompt。花括号字段是从当前项目已选资产组装的具名输入槽。

执行职责：短剧对白与配音拆分师。根据剧本原文、人物库和结构化分镜，生成逐句配音清单。

【人物规范名】
{characters_lib_name}

【人物介绍与称呼映射】
{characters_introduction}

【分镜 JSON】
{storyboard_json}

【剧本原文】
{input}

分集：{episode_key}
来源版本：{source_versions}

规则：
1. 按原文顺序提取明确需要发声的 dialogue、inner_monologue 和 voiceover；排除动作、场景描述、标题和纯画面信息。
2. content 必须逐字保留可听文本。不得为多音字改写正文；易误读内容写入 pronunciation_notes，供 TTS 的读音参数处理。
3. speaker 优先使用人物库规范名。通过人物介绍解析“我”、亲属称呼、职位和别名；无法可靠判定时使用 narrator，不得猜测具体人物。
4. matched_shot 先按文本证据匹配，再校验说话者和顺序。只能引用分镜中的 shot_number；无法可靠匹配时为 null。
5. emotion 使用简短可表演词，emotion_strength 为 0.1–0.5；不要把普通对白默认写成高强度。
6. 一个原文语句对应一项，不合并不同说话者，不拆散同一连续语义单元。

只返回严格 JSON 对象：{"episode_key":"...","source_versions":{},"lines":[],"voice_bindings":[],"unresolved":[],"approved":false}。lines 每项必须且只能包含：line_index、speaker、line_type、content、emotion、emotion_strength、pronunciation_notes、matched_shot。line_index 从 1 连续递增；pronunciation_notes 为字符串数组；matched_shot 为 {"shot_number": 正整数} 或 null。无可配音文本时 lines 返回 []。voice_bindings 记录用户已确认的 speaker、Provider、模型和 voice_id；任何说话人未绑定、读音未确认或参数未确认时写入 unresolved，approved 必须为 false。
